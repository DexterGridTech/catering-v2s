# Test closed loop

- `STATIC_PASS_NOT_DYNAMIC_PASS`: static/unit proof cannot be described as Testcontainers, DEV, seed, L2, browser, business, cleanup, UAT, or performance success. Dynamic status remains `NOT_RUN_AWAITING_SEPARATE_AUTHORIZATION` until its managed runner, business result, and cleanup evidence exist.
- `FAILURE_TAXONOMY_IS_TYPED`: environment absence, test failure, and harness failure remain distinguishable as `ENV_*`, `TEST_*`, and `HARNESS_*`; wrappers preserve the deepest first failure and expose last-known-good and broken-boundary evidence. For a non-zero remote Gradle test, R5 must read the archived JUnit XML and classify the explicit assertion marker or deepest causal throwable/message into `failureCategory` before considering Gradle's wrapper marker; a generic `REMOTE_GRADLE_EXIT_NONZERO` must not hide available cause evidence. The classification test must pair a generic Gradle wrapper marker with a concrete JUnit cause, prove JUnit wins, and prove the chosen code is wired into the manifest execution failure. A failed test task may exit during `@BeforeAll` before writing `backend-acceptance-result.jsonl`; success-only business evidence is required only when both the target test actually ran and the remote Gradle exit status is zero. On failed execution, do not replace the JUnit first failure with `EVIDENCE_ARTIFACT_REQUIRED`; preserve the original category, leave business `NOT_RUN` until real business evidence exists, and report cleanup separately. If no JUnit cause can be recovered, preserve a specific Gradle marker; if only the generic wrapper marker remains, record `GRADLE_TEST_FAILURE_DETAILS_UNAVAILABLE`, retain logs, and do not retry until the classifier and its red control are repaired. A repeated opaque category counts as a repeated failure family; freeze business progress at its second occurrence rather than assuming distinct causes. A cross-process rendezvous in an acceptance test must race its observation future against the owned child process exit, report a distinct observation-deadline marker, and retain allowlisted client/TDS stage diagnostics; a gate timeout must not mask an already-exited client or an earlier server-stage failure. Add focused red controls for both early child exit and an unobserved gate deadline, and never lengthen a timeout to hide missing progress. Java test-source changes must also pass the repository Java compile gate before another managed acceptance run; passing Node or structural tests does not prove Java test sources compile. The raw wire client must preserve exact stable `TERMINAL_WIRE_*` failure markers for diagnosis, record server-close code plus a protocol-allowlisted reason, and collapse unknown errors/reasons without emitting raw messages, credentials, or payloads. One-shot child termination is also a distinct diagnostic case: on a handled OS signal, log its allowlisted last stage, correlation marker and process identities before preserving the conventional exit code; the parent records the safe signal summary, elapsed time, output shape and first assertion marker before asserting, then records the signal again after cleanup to distinguish external termination from its own stop request. Never copy raw stderr/stdout; the static test must fail if either side stops recording this boundary. For the managed remote Testcontainers resource preflight, record an explicit `PASS`/`FAIL` result for each container and volume query. Only mark the inventory `EMPTY` when both queries returned `PASS` and both result sets are empty; missing markers, non-zero exits, malformed rows, or unknown output must remain `UNAVAILABLE`, `PARTIAL`, or `INVALID` with valid observed IDs/names retained. Record cleanup separately: pre-workspace remote process/workspace cleanup may pass, but each Testcontainers resource component passes only when its own inventory query succeeded and found zero resources. A failed preflight must never be summarized as an empty inventory.
- `ASYNC_PROTOCOL_ERROR_DIAGNOSTICS_ARE_SAFE`: when production asynchronous protocol handling maps an unexpected throwable to a generic wire close reason, emit one structured record at that catch boundary before closing. Include a connection correlation id, a stage selected from a closed enum, bounded top-level/root throwable type names, and only a validated stable machine code such as SQLState; never include exception messages, stack traces, raw frames, credentials, or SQL. The acceptance failure summary must retain this allowlisted event. Unit-test the diagnostic projection with secret-bearing messages and wire that exact test into the static gate so it cannot silently fall outside `scripts/verify`.
- `ASYNC_POOLED_BUFFER_LIFETIME_IS_EXPLICIT`: when a pooled Netty/Spring message is released after the synchronous receive callback returns, retain it before asynchronous downstream reads and release exactly that extra reference on completion, cancellation, or setup failure. Scheduled diagnostics capture immutable scalar values before the buffer lifetime ends. Test upstream release followed by an asynchronous read, and structurally bind the retain/capture/release sequence to its owner. This applies to pooled reference-counted inputs; synchronous or unpooled data does not need redundant retention.
- `PARENT_CONTROLLED_CHILD_RESULTS_SURVIVE_EXIT_RACES`: for a long-lived child controlled through stdin, the child can consume a command and exit on a concurrent socket event before the parent's write/flush returns. Check child liveness around control writes, collect the bounded structured result when the child has exited, and assert the expected protocol/session outcome; keep unrelated pipe errors as failures and race marker waits against child exit. This applies to parent-controlled persistent protocol clients; one-shot request/exit clients are counterexamples. Prevention is the acceptance `SessionProbe` helper plus its structural source test.
- `ROUTINE_RUNTIME_COMMANDS_NOT_IMPLEMENTATION`: an authorized `backend-acceptance` invocation is a standalone managed test and does not require an implementation package. Its real HTTP contract/business output must be read directly.
- `BACKEND_ACCEPTANCE_REAL_SCENARIOS`: 当前 backend-acceptance 自动发现并运行 当前 80 条(不设上限,Dexter 2026-08-27 裁定去除原 80 条约束)真实 IAM、ORG、商业合同、asset、catalog、audit、extension、collaboration 与 business-channel 场景；原 provider 壳、共享 SPI 与 scenario registry 已下线，PERFORMANCE/CLEANUP verdict、baseline、exact-set 与 lane 控制均已退役。
- `EXPLICIT_NODE_TEST_DENOMINATOR_MUST_MATCH_DISCOVERY`: the health runner must keep every tracked `scripts/**/*.test.mjs` in its explicit declaration; a newly present test file omitted from the list is a harness failure, not permission to use a broad glob or to claim the remaining tests are healthy. The minimum repair is to register the file, retain the missing/duplicate red controls, and rerun the full explicit entry.
- `JAVA_SQL_SOURCE_ASSERTIONS_MATCH_ASSEMBLED_VALUES`: a source-level test that reads Java SQL constants must account for compile-time source representation before matching SQL semantics: Java adjacent string-literal concatenation and text-block line continuations can split one runtime SQL clause across source lines. Normalize only those assembly forms in the test's local source view, keep positive and red-mutation assertions on the normalized value, and retain Java compile/runtime proof for execution semantics. Do not weaken unrelated Java syntax or control-flow assertions. The prevention helper for catalog query-envelope source checks is `joinJavaSqlSourceFragments` in `scripts/test/catalog-inventory-query-envelope.test.mjs`; this applies to static inspection of literal-built Java SQL, not arbitrary Java source matching.
