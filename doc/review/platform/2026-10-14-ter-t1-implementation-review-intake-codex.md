| S-1 configuration rejection category | CONFIRMED | `serverConfigActor.ts` uses plain `Error` for both caller-provided invalid configuration and the MASTER-only gate. Runtime normalizes non-AppError exceptions to SYSTEM; `requestOutcome.ts` treats AUTHORIZATION as system failure. A normal malformed admin payload therefore enters the system-failure presentation path. | Add the server-config package's two typed definitions: VALIDATION for invalid payloads, AUTHORIZATION for non-MASTER mutation. | S-2 static policy ownership / constants | PARTIALLY_CONFIRMED | TDC owns `reconnectPolicy` even though `TransportConnectionOwner` consumes it. The TDC latency selector and sample cap use `latencyWindowMs`, but reducer pruning still hard-codes two-hour milliseconds. WebSocket 65,536-byte limits are duplicated in the TDC parser and send paths despite the canonical protocol JSON and generator. Remote-control keepalive's 15,000 ms value is duplicated between event and timer logic. Existing remote result count/residence definitions already have consumers and are not part of this defect. | Move reconnect policy definition to transport; use one latency window in all three consumers; generate protocol byte-boundary constants from the canonical contract; add one remote-control keepalive parameter and consume it at both sites. Do not merge unrelated timeouts or add dynamic catalogs. |
| S-3 integration policy duplication | CONFIRMED (now closed) | The original current-project-candidate → fixed-target conversion was duplicated in both integration assemblies; that portion was moved to the project-basic selector. A second same-root duplication remained: both assemblies supplied a callback that resolved the LiveKit effective URL and built `selectedSpace:revision`, while the T1 appendix assigns signal-configuration interpretation to remote-control. The callback made composition understand remote-control configuration semantics. | `createRemoteControlModule` now accepts the environment's `serverSpaces`; remote-control reads its own configuration through server-config's public selectors in `readRemoteControlSignalConfiguration`. The integrations only bind that environment input. Application interlock/route policy and shared part-key validation remain where they are. No new config owner or synchronization path was added. |

A response-body read failure is necessarily after a response began. | Keep only failures proven before a request attempt as not-delivered. Treat fetch/native execution and response-body failures with uncertain delivery as delivered-failure. Add browser/native focused cases proving unsafe requests are not replayed to another address. |
