## S-1 · CP 编号在详设与串行计划中指不同的东西(**五个编号错位**)

**位置**:详设 §2 CP 总览(第 37-47 行)· 串行计划 §2 总体串行边界(第 35-45 行)

| CP | 详设 | 串行计划 |
|---|---|---|
| CP-00 | **不存在** | 设计冻结 / 未决检查 |
| CP-01 | catalog 定义族与有界读取 | catalog 定义族与现行持久化事实(大致同) |
| **CP-02** | **商品 assignment/config 与首步原子创建** | **inventory public judgement、级联与复制编排** |
| **CP-03** | **inventory 前置、BOM 删除与 copy composition** | **edge contract / generated consumer chain** |
| **CP-04** | **edge/OpenAPI/generated 消费闭环** | **operations-admin 库管理与商品编辑** |
| **CP-05** | **operations-admin 交互与刷新** | **copy preflight/execute 与 acceptance 场景** |
| CP-06 | 真实业务验收与静态/focused proof | 静态、focused、acceptance、独立复核(大致同) |

**根因**:串行计划插入了 `CP-00`,其后整体**错位一位**,而两份文档都用同一套 `CP-0X` 编号。

**影响面**:详设内引用 CP 编号 **10 处**,计划内 **14 处**,共 24 处交叉引用全部歧义。
实施者按「做 CP-03」执行时,读详设得到 inventory/BOM/copy,读计划得到 edge 契约链 —— **两份指令不同**。

**这是 R5 的复发**:2026-08-19 的复核里我把同一形状记为 N(「详设与串行计划 CP 编号冲突,5 个 id 指不同的东西」)。
同一形状第二次出现,**这次升为 S**。

**同族全集扫描**(三份文档共享的标识符逐类判定):
- `CP-0X` ⇒ **错位,本条**;
- `CATLIB-IA-01..09` ⇒ 仅 IA 使用(9 个),详设与计划零引用,**无冲突** ✅;
- 场景 ID `catalog.*` ⇒ 仅详设使用(11 条),命名唯一,**无冲突** ✅;
- `FR-*` 需求 ID ⇒ 三份均零引用,**不适用**。
⇒ **四类中仅 CP 一类有问题。**

**最小修复(二选一)**:
① 串行计划把 `CP-00` 改名为非 CP 前缀(如 `PRE-FREEZE`),其后编号与详设对齐;
② 两份文档统一采用计划的编号,详设 §2 增补 `CP-00` 并整体后移。
**我倾向 ①** —— 设计冻结不是实施 checkpoint,与其余六个不同类。

**是否需 Dexter 裁决**:否。
