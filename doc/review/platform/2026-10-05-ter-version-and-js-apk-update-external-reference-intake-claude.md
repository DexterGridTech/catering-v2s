## 3. 逐项 disposition

### S1：安装取消与人工重试

**CONFIRMED；取消及不提供手工重试均已按 Dexter 裁决修订。**

修改前 R-10/R-11（161～171 行）没有把用户取消与工件技术失败分开，165 行承诺人工重试却未给入口。当前正式需求 R-10（171～178 行）、R-11（182～186 行）、V-16/V-18（278/280 行）明确：用户取消保留固定任务，不记坏包，在本应用可呈现时按 N 再提醒；仍进行/未知安装不能重派。系统签名/文件等真实技术失败仍为终态。A 负责分类及真实再次确认，C 负责完整 N 调度，未把 C 全部义务塞回 A。

官方 [PackageInstaller STATUS_FAILURE_ABORTED](https://developer.android.com/reference/android/content/pm/PackageInstaller#STATUS_FAILURE_ABORTED) 定义包含用户拒绝权限、会话主动放弃等原因。它支持“不能仅按 aborted 码推定所有用户取消”的最小修正，不证明目标设备能用一个码区分全部来源。实际目标 API/上下文映射留 A；无动态 proof。

两个选项已交 Dexter；Dexter 确认不增加手工重试，正式需求 R-10/V-17 与阶段分工已同步。没有新增页面/command，原承诺已移除。S1 的产品缺口已关闭；实际 installer 分类及等待流程仍未实现/运行。

### S2：FULL 内嵌旧 JS 的中间数据窗口

**CONFIRMED；预下载 HOT 直接首启是另一个产品流程，本次不采纳。**

修改前 R-06/V-10（121/245 行）允许原 JS5→FULL 内嵌 JS4→HOT JS6，但只描述最终不降级，没有明确 JS4 读取 JS5 持久数据及任务的发布证明；R-14 的 HOT 保护不保证 FULL 内嵌启动可回退。这是前轮审查实际漏项，旧 GO 不足以豁免。

当前 R-06（125 行）、V-10（272 行）、A 工程准入（383 行）补真实前驱写入→内嵌包启动/读取→HOT 续接的兼容证明。无法证明不能放行该来源，不假设“APK 更新天然数据安全”。最小修正是发布准入及真实测试，不是全局 schema 迁移/备份框架。

预下载目标 HOT 并让新 APK 第一次启动直接加载它有潜在价值，但改变已确认 FULL→新启动→HOT 顺序；闲时 HOT 还不能靠预加载绕过 M。是否改流程须 Dexter；目前不加第二路径，也未验证新 native 首启加载该 HOT。这个替代不作为原方案必然不可行的证明。

### S3：整进程重启替代进程内 reload

**PARTIALLY_CONFIRMED。**

`apps/terminal/application/base/android/android/src/main/java/com/catering/v2s/terminal/application/base/android/TerminalAppControlModule.kt:17` 调用 ReactHost.reload；没有证明精确选包或整进程重新拉起。正式需求原来未比较替代，而不是已经不可更改地选择 reload。

当前 R-13（210 行）、V-24（286 行）、A 工程输入（383 行）要求 A 用当前解析版本/设备条件比较并选一条路线。整进程冷启动可复用入口，但任务落盘、实际自动拉起、双屏恢复及跨启动身份仍需证明。官方 [Android 后台启动限制](https://developer.android.com/guide/components/activities/background-starts) 说明启动 Activity 受条件限制；不能据此断言本项目一定不可重启，也不能断言杀进程后所有难点自然消失。需设备 proof，不先强制整进程默认或增加两套加载器。

### S4：原生无法猜业务数据兼容性

**CONFIRMED，按 Dexter 新裁决闭合需求依据，发布证据仍 NOT_RUN。**

该纪律不是对任意违规包的自动安全保证，不能用“未显示页面”推导“未写数据”；成功确认后不再自动回退。没有追加无限历史兼容矩阵。

## 4. 同根回读与防再犯

本次按问题族回读 R-01/06（身份/配对）、R-09～14（固定、安装、重启、数据写入）、R-15（实际/最近报告）、§17 与 §20 全部 A/B/C 相关行；同步了场景及阶段分工，不仅改命中段落。源码读取只证实目前 reload 和公开 command；没有把方法存在当作更新能力或可运行测试入口。

可复用失败模式：

1. 多阶段更新不能只断言最终目标；中间可执行版本也是数据读取者，需要前驱写入/中间读取/续接反例。
2. 回退的业务可读条件必须有发布证明来源，原生不能凭 startup timeout 推导 schema 安全。
3. 同版本数字不是同内容证明，外部分发安装包也是身份链的一环。
4. 用户选择等待与技术失败分开；固定策略的长期阻塞应向产品明确，不暗加恢复框架。
5. 既有 ready 与状态变化合并同一报告事实；不因增加运维可见性复制账本或扩张任务历史。
6. 技术替代比较必须承认可行替代，不能拿一次额外部署成本当不可能，也不能把冷启动当自动重启成功。

这些已落入正式条款、V-09/10/16/24/25/28/29、A 工程输入及本 intake checklist。现阶段没有可运行的新实现，不编造测试 PASS；后续需按这些具体反例建测试。
