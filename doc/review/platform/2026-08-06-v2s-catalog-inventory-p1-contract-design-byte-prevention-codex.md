# 1. 结论

Claude 的 `NO-GO — M=2 / S=2 / N=1` 成立。根因不是“少提醒 reviewer 一句”，而是当前流程把三种
不同事实合并成了一个 PASS：

1. schema 有 type、route 可达、生成物可编译；
2. 详设要求的业务字段、字段类型与已关闭 finding 已落到契约；
3. P2/P3 可以只实现当前 P1 字节而不再发明字段。

P1 只证明了第 1 层，却在 evidence 中把它表述成了第 2/3 层。`modelFieldOverrides` 是实现者临时写出的
最小字段集合，不是详设的规范源；checker 只拒绝空 closed object，不拒绝“合法但少字段”的 typed object。

# 2. 有限问题分母

本问题族不能只指向 `CatalogItemPage`：

- `contracts/openapi/catalog-inventory.openapi.yaml` 当前 72 个 schema；
- 详设 §3.4 的 25 个 read model 以及 `CatalogItemSaveRequest.sections`；
- 详设已关闭 finding 中的 4 个 `voidAvailability` 站点；
- 时间/金额/数量的类型约束；当前 `occurredAt` 有 6 个落点；
- 生成的 Java/TypeScript wire 与 OpenAPI 对应路径；
- P1 checker、evidence denominator、independent-review checklist。

反例边界：允许的自由描述属性 map 仍可开放；设计本身未冻结的产品语义不能由机器门擅自补全，必须先由
详设/需求决定字段名、nullable、类型与 owner。

# 3. 三层修复（推荐全部采用）

## 3.1 Independent review prompt / checklist

已更新 `doc/review/platform/independent-subagent-adversarial-review-input-checklist-template.md`：

- reviewer 必须在阅读作者 disposition 前读取详设的精确 heading 与 source-bound coverage matrix；
- reviewer 必须自己导出 expected nested field/type set，不得把 generator、fixture 或作者 field map 当 oracle；
- 必须做 design-to-byte diff，并对“删一个必需字段、删一个已关闭 finding、改一个时间/金额类型”做 red mutation；
- structural type/compile/reachability PASS 不得当作 payload completeness。

这能修复 reviewer 漏看，但不能单独阻止实现者漏做。

## 3.2 Machine gate

在现有 `scripts/check/catalog-inventory-p1` 内增加一个机械分母，而不是另起语义扫描器：

`contracts/policy/catalog-inventory-design-byte-coverage.json` 必须绑定：

- 详设路径、精确 heading、source SHA；
- 25 个 read model 与 whole-save 的 canonical nested field paths；
- 每个 path 的 type/format/nullable/closed-set 信息；
- 四处 `voidAvailability`；
- 时间、金额、数量约定；
- 生成 Java/TypeScript/OpenAPI 的目标路径。

门只做机械判断：expected path/type 与当前 OpenAPI/generated byte exact-set；缺 coverage matrix、`PENDING`、
缺 path、extra/changed type 均 fail closed。真实 red mutation 至少包括：

1. 删除 `CatalogItemPage.items[].priceGranularity`；
2. 删除四处 `voidAvailability`；
3. 把 `occurredAt` 从 epoch integer 改成 string；
4. 把 `CatalogItemSaveRequest.sections` 退回 `{factType,revision}`。

机器门不判断“详设字段是否业务正确”；那仍由 Dexter/独立 reviewer 判断。它只防止实现偏离已经冻结的
coverage matrix。

## 3.3 Package exit / evidence

P1 evidence 不能只报告 `operations/shapes/cases/compile`。新增必须对账：

- `designFieldDenominator`；
- `designFieldExactMatches`；
- `closedFindingRegressionDenominator`；
- `typeConventionDenominator`；
- `generatedTargetParity`。

只要其中一项未执行或不是 PASS，implementation package 不能标 GO。`typedSchemas` 必须改名/拆分为
`schemaShape` 与 `designFieldCoverage`，避免证据语义过宽。

# 4. 为什么不只改一个地方

| 方案 | 结果 | 判断 |
|---|---|---|
| 只改 reviewer 提示词 | 依赖 reviewer 记忆，作者仍可生成最小骨架，容易再次假绿 | 不足 |
| 只加关键词/字段数量门 | 会把语义伪装成 checker，字段改名或合法遗漏即可绕过 | 拒绝 |
| 只把所有字段写进 generator | generator 既当规范源又当实现，仍无法证明没有偏离详设 | 不足 |
| **详设绑定 coverage matrix + 机械 exact-set + blind diff + package exit 分母** | 规范、实现、审查各有单一职责，缺字段会在实现门直接红 | **推荐** |
