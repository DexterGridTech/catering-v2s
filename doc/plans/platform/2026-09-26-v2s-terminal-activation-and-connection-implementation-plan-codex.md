#### TDS runtime constructor selection

Spring stereotype classes with overloaded constructors must identify one injection constructor with `@Autowired`; otherwise Spring can fall back to a missing no-argument constructor and fail before the TDS listener becomes ready. The `tds-constructor-assembly` gate runs the ArchUnit production scan, selected/unselected-constructor fixtures, the real protocol bean's `ApplicationContextRunner` test, `TdsRuntimeSettingsTest` for typed runtime-property binding and fail-closed capacity validation, and `TdsWebSocketMessageOwnershipTest` plus `TdsWebSocketConnectionTest` for inbound and outbound pooled-message lifetime, along with `TdsBlockHoundTest` for the pinned event-loop blocking detector, in one isolated TDS Gradle test JVM. This catches bean/configuration and BlockHound wiring failures before a managed TDS run and keeps their JUnit XML evidence in the registered test task.

#### Step 7 implementation note · V-S10/V-S12 listener and outage proof

### Step 3 implementation note · D-40 current-generation ended credentials
