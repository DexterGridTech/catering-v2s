## 1. 用户任务、现状与选择

终端用户在登录、会员资料、顾客确认、管理员 PIN 或拓扑地址等现有输入场景中，打开自绘虚拟键盘后仍应看见**原本形状不变的表单／弹窗**，清楚找到正在编辑的完整输入框，并能用符合任务的按键完成输入。Dexter 要解决的是三种相连的失败：键盘外框在不同设备上成为留白的定宽圆角卡片；全键盘缺少空格及 URL 常用符号；键盘占据正常布局高度，使表单和按钮被重新排布，切换输入框时还可能沿用旧高度／位置。

可行但不采纳的办法是继续让键盘参加正常布局，并为每个页面分别调整 flex、高度和滚动。它会把同一避让问题复制到普通页面与弹窗，且无法保证“提交”等控件相对表单的位置不变。本需求选择所属 surface 底部的覆盖层：键盘独立进退，非键盘 UI 保持尺寸和内部布局；按中心规则平移（无论是否达到上限）后焦点框仍不完整可见时，在固定尺寸内部滚动区域补足。这个选择只定义可观察结果，不规定 React 组件树、动画库或实现文件。

本批是已有输入基础能力的横切优化，**不创建新业务 Journey**。真实消费仍由既有页面／part 提供；某组合没有生产消费者时，用与生产相同输入公共面的受控 harness 验证键盘能力，不能为测试把 sample-only 字段扩成业务字段或给副屏编造新页面。

## 2. 范围、坐标与名词

- 四种程序虚拟键盘：`full`、`alpha`、`numeric`、`financial`。A/B/D 对四者都生效；full 的 URL 字符层只作用于 `full`；full 与 alpha 的字母动作行采用同一位置约定（Shift 在 `a` 左侧、Space 在 `z` 左侧）；“取消 CAPS 逻辑”按 Dexter Q5 的字面范围作用于当前有 CAPS 的 `full` 和 `alpha`。
- 适用承载：laptop、mobile、单机双屏的各自可用 surface 与 Web 实际输入 frame；PRIMARY、SECONDARY 只在现有合法 consumer 或受控 harness 上验证，不因此增加业务拓扑。程序键盘与系统 IME 是不同 owner，本需求不改系统 IME。
- `surface` 指当前 `InputSurfaceFrame` 实测逻辑承载矩形。宽度 `W`、高度 `H` 只能取该 surface 的当前有效本地测量；双屏各算各的，不从全局 window、物理像素、另一块屏或静态 `terminalSurfaces` 推断。当前生产输入均使用 `surface` placement。设计按 N-3 采用正式移除零生产消费者的 `field` placement；实施须同步删除类型、注册/渲染分支、相关测试、README 与 public invariant，不保留兼容别名或窄宿主 harness。本轮仅冻结该设计决定，不改源码。
- 稳定态的 `K` 指**当前键盘外框的真实逻辑高度**；异布局交接中的 `K` 指**当时实际可见的底部键盘遮挡高度**，不是目标键盘估值、旧布局估值或两个高度的简单平均。计算终点时使用目标键盘稳定态高度 `K_B`。`centerY` 是焦点输入框在未受本次键盘平移影响时、于所属 surface 坐标内的中心纵坐标。目标中心线是 `(H-K)/2`；“完整可见”要求焦点输入框的整个可操作边界框在键盘上沿以上、surface 与有效裁切边界内，而不只中心点可见。
- “非键盘 UI 不变形”指页面／弹窗及其控件的布局盒尺寸、换行、相互布局关系和按钮在表单中的位置不因键盘出现／消失被重新计算。允许本需求规定的整体平移和必要的**固定尺寸内部滚动**；滚动改变视口所见内容，不等于改动内容布局或单独上移提交按钮。

## 3. 必须满足的产品要求

### VK-R01 · 四布局的键盘外框横向填满

无论键盘类型、laptop/mobile、横竖向、PRIMARY/SECONDARY 或 Web 当前窗口宽度，只要该 surface 容量受支持，键盘**外框**的左右边界就与所属 surface 可用横向边界重合，底边贴该 surface 底边。不得保留按类型／设备固定的 820、560、330 宽度、`maxWidth`、两侧外 margin 或居中浮卡。frame 宽度变化后应按最新本地测量重新铺满，不出现旧宽度闪帧、横向滚动、裁键或跨屏取宽。

按 Dexter 对 S-3 的裁定，所有键帽列轨按最终外框宽度填满，不设置居中限宽。键宽按布局列数、真实 padding 与 gap 计算；laptop `W=1280` 时 full/alpha 为 118、numeric/financial 为 412；mobile `W=360` 时分别为 30 与 110。外框全宽与键位无重叠、无截断须同时成立；如果某逻辑 frame 低于已有受支持宽度／触控容量，使用现有可诊断、可恢复的不可支持路径，不能显示半截键盘或制造已获虚拟焦点却无法输入的死状态。

### VK-R02 · 外框四角为直角

键盘外框四颗角的圆角均为 `0`，且 Web、Android 与两种 integration 的真实渲染不能被其它 primitive/token/style 覆盖回圆角。Dexter Q2 只裁定**外框**，不要求单个键帽也改为直角。主题色、键区层级、按下／选中反馈仍由现有键盘主题契约管理；本需求不借方角理由改写业务主题。

### VK-R03 · full 键位交换、空格与 CAPS 退役

`full` 的 home 行原 CAPS 位置改为唯一 Shift，末行原 Shift 位置改为空格；`alpha` 同样采用三行字母布局的同一动作位置：home 行首项为 Shift（在 `a` 左侧），末行首项为空格（在 `z` 左侧）。空格键必须真的向当前 selection 插入空格，而不只是标签。保留原字母顺序、删除和完成入口，具体键帽尺寸与绘制由后续 IA 定。`full` 与 `alpha` 均不再显示 CAPS 键、CAPS 锁定态、长按 CAPS 手势或残留的不可见持久大写状态；两者都保留可操作的一次性 Shift，且 alpha 不得留下空的伪按钮。

“简单 Shift”只接受普通短按，不提供长按状态机：按下可进入／退出待生效态，下一次**成功插入**的字符按 Shift 对应标签写入后恢复普通态；未插入字符的动作不应冒充已经消费了一次输入。现有 `editText.ts` 即使因 `maxLength` 截断为零也会清除 Shift，这一点须按新要求改变，不能误列为必须保留的旧行为。待生效 Shift 只属于**当前字段的当前焦点会话**：该会话是 `keyboardState.activeFieldId` 等于该字段且输入 owner 为 `virtual` 的区间，依据现有 `useInputFocusController.ts` 的 owner／activeFieldId 状态；一旦真正切换到另一字段、改由系统键盘接管、完成／focus-next、显式失焦／收起、切换 focus scope 或字段卸载，即清除旧字段的待生效态，既不迁移给新字段，也不在返回旧字段时复活；同字段仅因 React Native 的中间 blur 事件而没有实际失去输入 owner 时，不得误清。`maxLength` 等导致零字符插入但焦点会话未结束时则仍保持待生效，直到成功插入或用户再按 Shift 显式取消。Shift 的待生效状态、键帽标签和实际编辑结果必须一致。既有 selection、maxLength、退格、完成／focus-next、失焦与快照语义继续成立；字段校验仍由字段负责，键盘不替 URL、密码或工号字段制定业务允许字符。

### VK-R04 · full 的数字行字符态覆盖 URL 输入

在 `full` 上按 Shift 后，数字行从 `0–9` 的数字键帽变为字符键帽，点击时实际插入当前可见字符，不得“显示字符、写入原数字”。普通态仍可直接输入 `0–9`。URL 符号分母为数字行 Shift 层十项 `: / . ? & = - _ % +`，不提供额外符号行。每项都必须可从键盘上**可见、可发现、可点击**的路径输入，不能依赖长按、系统 IME、隐藏手势或复制粘贴。

十个数字槽位与十个字符一一对应。full 保持四行，不增加额外符号行；交互／IA 必须给出十项的键位、普通数字态返回方式、标签和实际输入的逐项对照。URL 字段是否接受空格、值如何校验仍由其字段原有规则决定。

### VK-R05 · 键盘覆盖，不缩短非键盘布局

程序键盘从所属 surface 底部**覆盖**非键盘 UI，不参与后者的正常高度分配。弹起、切换、收回时，普通页面和弹窗的外框、表单行列、控件宽高、换行、按钮在表单中的布局位置保持不变；不得通过把 `surface-content`、弹窗或表单容器减去 `K`，让 flex 重排或把“提交”按钮单独推到上方来实现避让。若字段在固定尺寸的内部滚动区域而按钮在其外，滚动可改变二者的屏幕相对位置，但不能重排二者的布局盒或让按钮单独响应键盘上移。键盘应在内容上层，命中、遮罩和焦点保持正确；点非输入区域收起须遵从所在 focus scope 的现有关闭语义，不能把当前 business scope 的点击关闭硬套到管理员 PIN 等受保护 scope。弹窗遮罩继续覆盖应覆盖的 surface，不能随弹窗内容平移露出背景。

### VK-R06 · 中心线、位移上限与完整可见优先

打开键盘或切换焦点时，以当前所属 surface 的 `H`、目标键盘的 `K` 和焦点输入框的未平移 `centerY` 计算第一步理想整体偏移：

```text
targetLine = (H - K) / 2
idealOffsetY = -min(K, max(0, centerY - targetLine))
-K <= offsetY <= 0
```

输入框中心在目标线之上／恰在线上时，正常情形不整体上移；在目标线之下时，非键盘内容整体上移，使中心尽量到目标线。Dexter 同时裁定**焦点输入框完整可见优先**：仅中心正确而输入框边缘被键盘、surface 或内部裁切挡住仍不合格。整个内容层的上移量在任何稳定态和动画帧中均不得超过该帧的 `K`：稳定态为当前键盘外框高度，异布局交接中为当时实际可见的底部键盘遮挡高度；不能靠假测量、过冲或平移弹窗遮罩绕开上限。`H=800,K=300,centerY=700` 时理想需上移 450，但实际整体上移至多 300，中心停在 400；不得谎称到达 250。

按中心规则平移（无论是否达到上限）后焦点框仍不完整可见时，Dexter Q6 允许在**不改变外框尺寸**的内部可滚动区域继续滚动，直到输入框整个边界框可见且可操作。滚动须使用平移后真实可见区域计算，不得把已有平移重复计入。对于键盘出现前已完整可见、输入框高度不超过 `H-K` 的样本，仅中心规则加 `K` 上限即足以让其保持完整可见；需要内部滚动的实际入口是内部滚动视口的上缘或下缘裁切、focus-next／程序化聚焦到屏外或已被裁切的字段，以及输入框高度大于 `H-K` 的容量情形。最后一种情形仅靠滚动也不可能把整个输入框放进可见带。若键盘以上实际可见空间连输入框本身都容纳不了，或缺少可滚动范围，则不能声称通过：应呈现可理解的容量不足状态和可恢复动作，保持草稿／焦点 owner 安全，不得静默给出一条被遮挡的输入路径。Q4 允许页面／弹窗的其它部分在避让时被 surface 裁出，但不能牺牲焦点框完整可见来保持整张弹窗在屏内。

### VK-R07 · 同步进退与输入框切换

- 首次弹出时键盘自下而上进入；若内容需要位移，非键盘层的整体平移和必要内部滚动在**同一段时间**完成。收起时键盘自上而下退出，内容同时回到无键盘位置；不能先卸载再把消失冒充退出动画。键盘不需避让时内容保持静止。
- 从 A 切换到 B 时，重新取得 B 的键盘布局及真实 `K_B`、B 的未平移位置、当前 `H`、当前滚动与裁切事实，再求 B 的平移和必要滚动。不能沿用 A 的高度／offset，不能从已平移的屏幕坐标再叠加一次旧 offset；跨 surface 切换分别按各自 surface 求解。
- 若 A/B 所需键盘**布局类型相同且仍在同一 surface**，已显示键盘**保持原位**，不先收起再弹出；内容仍须在一次过渡中平滑到 B 的避让位置。Shift 造成的数字／字符标签和输入值变化是同一键盘内部的 modifier 状态，不是“换键盘”，不能因此重弹。同布局遇本地 frame resize、实际 `K` 或外框尺寸改变，应在原位适配并重算避让，也不等于换键盘。若布局类型不同，**新键盘先在旧键盘下层升起，旧键盘再向下退出**；交接期间实际可见的底部键盘遮挡高度在 `K_A` 与 `K_B` 之间单调变化，内容平移／滚动与这一交接处于同一整体时间段，且每一帧的上移量不超过该帧实际可见遮挡高度。不得先按目标高度瞬间压低内容、让新旧键盘相互掏空可见遮挡、只瞬间替换键帽或让内容晚一拍追赶。跨 surface 切换由各自 surface 的键盘分别交接，不能把一块屏的实例“保持原位”在另一块屏上。
- 快速 A→B→C、动画中收起、frame resize、弹窗打开／关闭，都以**当前可见状态**转向新的目标，不叠加过期动画，不跳变、不留下残余平移。新旧键盘高度不同时，交接过程仍须满足位移上限、焦点可见性及正确的遮罩／命中；具体逐帧高度归属和曲线由详设给出，不能只核两个端点。

### VK-R08 · 保留既有输入与容量安全边界

保留虚拟／系统 owner 互斥及双向切换首击不丢失、局部测量和未测量态、输入 registry、原子快照、focus-next／complete、失焦、可选字段不阻断决策、跨 layer 焦点恢复、按键级 testID／可访问反馈，以及**适用 focus scope 内**的非输入区收起。`nativeLess` 的管理员 PIN 虽没有普通 `PrimitiveInput` 测量 ref，也必须以其**真实可见控件**作为焦点框测量锚点；不能借固定位置、历史 POC 坐标或“无 ref”跳过 R06。它当前也没有现成的 `InputScrollArea`，故若触及整体位移上限还需内部滚动，详设必须给出真实的滚动承载或明确容量不足条件，不能把“允许滚动”误写成“PIN 已可滚动”。

保留当前键盘键位的触控可达性、宽度不足和高度不足的显式不可支持／尺寸恢复路径，以及不超过 320 逻辑单位和 surface 高度 50% 的既有 dock 高度上界，除非后续正式设计以可证伪容量反例取得新的产品裁定。宽度容量必须按**最终实际渲染的全宽外框及真实内边距／键间隙**判断，不能一边用 surface 宽度算“支持”，一边渲染更窄的 dock 导致键帽碰撞或裁切。旧 `MIN_CONTENT_HEIGHT=208` 是“内容被 dock 收缩”的派生前提，**不得**直接作为新覆盖层避让成功的 oracle；后续详设须重新定义可见带与容量判据。旧的主题、业务字段和系统 IME 规则没有被本需求默默放宽。

## 4. 消费者和验证分母

下表只列现有输入消费者类型，不为覆盖率创造新业务字段。实施前须按当前源码重算同族输入注册与 placement 分母；本稿的路径是设计入口，不把历史行号当当前事实。

| 布局／场景 | 当前真实消费及目标观察 | 特殊边界 |
| --- | --- | --- |
| full | sample-staff-auth 工号／密码、sample-member-desk 姓名等现有 full virtual 字段 | 空格／符号不能破坏原字段的 maxLength、selection、提交规则；system 字段不被强制改 virtual |
| alpha | MemberForm 的 sample-only 英文字符探针 | CAPS 移除；Shift 在 `a` 左侧、Space 在 `z` 左侧；不入会员 payload／dirty；PRIMARY-only |
| numeric | MemberForm 电话、CustomerMember 年龄、管理员登录 PIN | 年龄上限与可选语义不变；PIN 的 `nativeLess` 锚点必验 |
| financial | MemberForm 的 sample-only 金额探针，以及现有拓扑主机地址输入 | sample 探针不入业务；拓扑地址不会因为 full 获得符号层而自动改键盘类型 |

真实消费者只能覆盖它们本来出现的面。四布局在 laptop、mobile、PRIMARY/SECONDARY 与 Web resize 的公共能力由受控 input harness 补齐；harness 必须使用真实 input 公共面和键级动作，不得用一个纯公式单元测试冒充运行画面。`field` placement 按已裁定范围在实施中正式移除，不进入能力或画面分母。生产没有自然入口的组合记录 `NOT_COVERED_BY_PRODUCT_CONSUMER`，不伪造业务页。普通页面与弹窗、输入框中心在线上／下、位移饱和与内部滚动、同／异布局 A→B、快速切换、双屏隔离和不可支持恢复均属独立验收分母。
