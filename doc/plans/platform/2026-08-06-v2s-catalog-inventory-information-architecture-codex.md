## 0. 设计结论

本期在运营管理后台新增一级导航 **商品与服务**，依次提供：

1. **门店商品管理**：面向 `STORE` 数据节点，集团/大区/项目/门店角色可进入；
2. **门店库存管理**：面向 `STORE` 数据节点，集团/大区/项目/门店角色可进入；
3. **品牌商品管理**：面向 `HEAD_COMPANY` 数据节点，集团/总公司角色可进入，页面内再选择该总公司已获授权品牌。

三个页面形成一条清晰任务链：先维护可复用商品事实和库存/BOM定义，再在门店查看与维护真实余额、流水和变化。菜单、销售发布、订单、生产运行时均不混入本期。

本 IA 已收到两个 Dexter 明确确认的设计点；其余逐项确认集中在 §12.2：

- `DEC-IA-01`（Dexter 已确认）：三个二级菜单按“门店商品管理 → 门店库存管理 → 品牌商品管理”的顺序排列；
- `DEC-IA-02`（Dexter 已确认）：继承 v4 的紧凑复合单元格，同时继续服从全局 `NameCodeText` 名码规范。商品主列按“缩略图+名称(编码) / 短名·分类·标签”分层；库存对象主列按“名称(编码) / 对象形态·分类·物料标记”分层。编码字号小一号、颜色弱一级。筛选命中的事实必须在复合单元格或其他默认列中可见。
- `DEC-IA-03`（Dexter 已确认）：商品搜索不是全局搜索。用户先在左树选定“全部商品/智能视图/商品形态/商品分类”之一，关键词只在当前节点定义的结果域内查询；切换节点即切换查询边界。`[树表视图|仅表格]` 是页面全局功能，放在与“商品字典”同一工具行的最左侧；品牌页的品牌切换器紧随其右。

`IA-CAT-LIST-012`：关键词查询严格依附当前左树节点。查询参数由
`selectedTreeNode(kind, ref) + keyword + status + governance + source + tags + cursor` 共同构成：

- 选择商品分类时，结果域固定为该分类及其后代（`includeSubCategories=true`），关键词只搜索此域；
- 选择商品形态或智能视图时，结果域分别是该形态或该派生视图，关键词仍只在该域内搜索；
- “全部商品”也是用户显式选择的一个结果域，不存在脱离树节点的跨域关键词框；
- 切换树节点保留已输入关键词并立即在新结果域重新查询，便于用同一关键词比较不同分类；同时清空分页、选中行与展开行并取消旧请求。树节点点击是离散提交，不额外防抖；连续点击必须中止上一请求、按 generation 只接纳最后节点响应，并对完全相同的有效查询去重。关键词只在用户按 Enter 或点击搜索按钮时提交，避免每次键入与节点切换叠加请求。切换智能视图时，状态/治理/来源按系统视图规则清除或锁定冲突值；
- 搜索请求和返回都携带当前 scope、owner、tree-node identity 与 generation，旧节点响应不得覆盖新节点。

左树顶部“搜索树节点”与右侧“在当前结果域搜索商品”是两套不同能力：前者仅在浏览器内按分类
名称/编码过滤树并展开匹配路径，不触发商品请求；后者才进入 owner 商品查询。两者不得共用 state、
placeholder、日志 operationId 或测试 locator。

`IA-CAT-LIST-013`：全局工具行与结果域工具行不可混排。第一行左侧固定
`[树表视图|仅表格]`，右侧为商品字典/复制/新建；第二行位于表格结果域内，显示当前节点、局部关键词、
其余筛选、批量操作和列设置。视图切换只改变左树与表格的组合呈现，不改变当前结果域或查询条件。

`IA-COPY-006`：预检“结构冲突”严格使用九类判别位：

| 对象         | 同编码结构阻断位                                                                               | 非结构差异可确认复用               |
| ------------ | ---------------------------------------------------------------------------------------------- | ---------------------------------- |
| 商品         | 商品形态；SKU 结构指纹（按 `skuCode` 排序后逐项绑定排序后的 `(attributeCode,valueCode)` 组合） | 名称、短名、说明、图片、标签、分类 |

| 销售单位     | `unitKind`                                                                                     | 名称、precision                    |
| SKU 销售属性 | 无                                                                                             | 名称、展示顺序                     |
| SKU 属性值   | 所属属性维度                                                                                   | 展示名、排序                       |
| 商品处理标签 | `tagKind`                                                                                      | 名称                               |
| 库存对象     | 对象形态、消耗单位                                                                             | 阈值、允许负库存                   |
| BOM          | owner 类型                                                                                     | 版本备注                           |

`C-19` 已裁决采用以下 canonical matching tuple。预检界面必须把实际 tuple 显示在“判同编码”列，
不能仅显示模糊“同编码”：

| 对象                                              | canonical matching tuple（均先带目标 owner scope）                          |
| ------------------------------------------------- | --------------------------------------------------------------------------- |
| 商品/分类/标签/销售单位/SKU 销售属性/商品处理标签 | `(objectType, code)`                                                        |
| SKU 属性值                                        | `(attributeCode, valueCode)`                                                |
| SKU                                               | `(itemCode, skuCode)`                                                       |
| 库存对象                                          | `(targetType, itemCode, skuCode?)`，与需求兼容矩阵的“所属商品/SKU 编码”一致 |
| BOM                                               | `(ownerType, itemCode, skuCode?/optionValuePath?)`                          |

库存对象不另设自身编码；它的稳定身份由所关联商品/SKU 的不可变编码组成。UI、owner API、
数据库唯一约束、mapping preview、digest canonicalization 与复制预检必须逐字符采用同一套 tuple；
禁止任一层另造库存对象编码或改用内部 ID 判同。

SKU 结构指纹不是第十类兼容对象，也不改变 SKU 的 canonical matching tuple。它是“商品”这一既有
结构判别位的子项：同一 `(itemCode, skuCode)` 命中后，如果属性值组合不同，必须把整个商品判为
结构不兼容；不得因编码命中而静默复用到另一套规格组合。

`IA-COPY-007`：相同直接复用；非结构差异必须用户确认后复用；结构不兼容阻断，禁止“接受并忽略”。本期不建单位换算/迁移系统。

`IA-COPY-008`：预检是读任务，但判同/兼容性解释仍由各 owner 提供；执行携带 digest 与 expected versions，同一 `REQUIRED` 事务内由三个 owner 各自复核，漂移返回 typed `STALE_COPY_PREFLIGHT` 并要求重做预检。
