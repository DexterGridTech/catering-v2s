## 1. 结论与事实来源

### 1.1 当前结论

V2S 只有一个“门店销售菜单”页面。页面继承 V4 已验证的单页工作台结构：

```text
全局门店上下文（运营后台已有，不在菜单页重复）
  └─ 门店销售菜单（唯一页面）
       ├─ 经营入口
       │    ├─ 渠道选择 + 管理菜单
       │    └─ 前台菜单 / 草稿菜单 / 操作记录 + 菜单选择 + 当前菜单动作
       ├─ 销售分区 + 销售项工作台
       └─ 当前任务的局部抽屉 / 确认弹窗
```

不建设菜单列表页、菜单编辑页、发布详情页、有效视图页或诊断页。品牌和总公司没有菜单入口。

### 1.2 事实类别

- `[v6 正本]` 草稿可改、发布冻结；商品分类与销售分区不同；商品显式编入销售项；发布不等于终端已获取；同一入口可有多份菜单。
- `[v4 历史事实]` 单页工作台、左分区右销售项、局部抽屉、模式切换和菜单选择器已经被真实 Journey 使用；只读第一份菜单、虚拟分区和本地乐观排序都踩过坑。
- `[v2s 仓内事实]` 门店在运营后台使用全局节点上下文；商品列表以中文商品形态为关键识别信息；商品图片已有上传、替换、重试、设主图、上移、下移、删除交互。来源：`apps/frontend/operations-admin/src/features/catalog-management/ui/CatalogItemListTable.tsx`、`CatalogItemBasicEditor.tsx`。
- `[Dexter 裁定]` 只有门店有菜单；本批只做内部堂食/外带渠道；同一入口可同时生效多份菜单；销售端自己判断使用哪份；本页必须吸收需求正本 §4.8 的 UI-01 至 UI-31。
- `[本稿推论]` 直接复用现有商品形态与图片交互，比为菜单另造选择器和图片组件更简单，也能减少用户重新学习。

## 2. 唯一页面

### IA-SM-PAGE-001 门店销售菜单

| 项目         | 定义                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| 入口         | 运营管理后台 / 商品与服务 / 门店销售菜单                               |
| 页内标题     | 不显示重复页内标题；页面从“经营入口”区块开始                         |
| 门店上下文   | 读取运营后台全局当前门店；页面内不显示第二个门店名称或门店选择器       |
| 当前范围     | `access_kind=INTERNAL` 且 `order_kind=DINE_IN/TAKEAWAY` 的门店经营入口 |
| 页面保持     | 当前经营入口、当前菜单、模式、销售分区、表格位置                       |
| 页面离开保护 | 存在未保存表单时才提示；草稿已保存但未发布不属于“未保存”               |

页面从上到下只有两层：包含两行控制的“经营入口”区块、当前模式的主工作区。经营入口区块不再拆出独立的“菜单工作区”区块。
局部抽屉和弹窗覆盖在当前页面上，关闭后焦点回到触发控件，不产生第二个路由。

## 3. 页面头部与模式

### IA-SM-CHANNEL-001 经营入口选择器

| 控件/状态            | 表达与动作                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 选择器               | 一行占满的下拉选择器；显示全部可维护的内部堂食/外带经营入口，单选                        |
| 选项内容             | 渠道名称、渠道模板名称、内/外部渠道、订单类型、渠道启用/停用、模板状态等关键识别信息     |
| 集合可达性           | 下拉弹层沿 owner `nextCursor` 增量滚动加载，不在页面显示入口分页或页码；第 21 项必须可达 |
| 切换                 | 刷新下方菜单选择器和主工作区，仍停留在本页；清空旧入口/菜单/分区的候选游标状态           |
| 管理菜单             | 选择器右侧的次按钮；打开当前经营入口的管理菜单抽屉                                       |
| 停用入口             | 可查看历史；更新到前台时阻断并说明“当前经营入口已停用”                                   |
| 项目级/团购/外部入口 | 不进入选择器；从外部深链进入时明确说明当前不做项目级菜单或该渠道采用商品对应关系         |

### IA-SM-MODE-001 模式分段控件

| 模式     | 主工作区               | 允许动作                            |
| -------- | ---------------------- | ----------------------------------- |
| 前台菜单 | 已发布的分区和销售项   | 查看；对销售项设置正常销售/人工沽清 |
| 草稿菜单 | 当前草稿的分区和销售项 | 编排、编辑、排序、删除、更新到前台  |
| 操作记录 | 普通操作记录表         | 查看，不进入诊断抽屉                |

模式切换只替换主工作区。不得使用“更新记录”“发布诊断”等扩大含义的名称。
模式分段控件与菜单选择器、当前菜单状态/时段/发布/刷新动作共用经营入口区块的第二行，保持同一水平行；窄视口只允许该行水平滚动，不拆成两个业务行。

### IA-SM-MENU-001 菜单选择器与菜单级动作

| 控件           | 形态               | 状态/行为                                                                                                  |
| -------------- | ------------------ | ---------------------------------------------------------------------------------------------------------- |
| 菜单选择器     | 可搜索下拉选择     | 列出当前经营入口的全部菜单；通过弹层滚动增量加载，不显示页面分页；只选择当前查看/编辑对象，不表达生效/失效 |
| 菜单摘要       | 选择器选项副文案   | `有未发布修改`、`与前台一致` 等草稿状态；不显示“唯一当前菜单”                                              |
| 生效与时段     | 次按钮             | 打开 IA-SM-ACT-001                                                                                         |
| 当前菜单动作区 | 菜单选择器右侧同排 | 显示状态、全天/时段、生效与时段、更新到前台、刷新                                                          |
| 更新到前台     | 主按钮             | 仅草稿模式可用；打开 IA-SM-PUBLISH-001                                                                     |

经营入口区块的第一行只负责经营入口范围与“管理菜单”；第二行负责模式、当前菜单和菜单级动作。经营入口选项中的渠道名称、启停状态、模板名称、内/外部接入、订单类型和模板状态保持单行展示，避免把同一个选择项拆成标题与副文案两行。

同一经营入口允许多份菜单同时启用。菜单选择器不得出现“切换生效菜单”的含义。

#### 经营入口与菜单集合的可达性澄清（旧规则已修订）

本节是 IA 确认后的 implementation-facing 可达性澄清，不改变页面层级或业务动作。“全部”表示用户能够沿显式控件到达每一项，不表示浏览器在后台自动抽干所有游标页：

- **历史方案（已被 2026-09-07 修订）**：经营入口卡片和菜单选择器在页面显示顺序游标分页。
- 当前经营入口选择器为一行占满的下拉选择器；选项展示渠道与模板关键维度，弹层滚动触发 owner `nextCursor` 增量加载；换经营入口范围时清空候选积累。
- 当前菜单选择器支持服务端关键词搜索，弹层滚动触发 owner `nextCursor` 增量加载；搜索词或经营入口变化时清空候选积累；当前已选菜单即使不在已加载选项中也继续显示。
- “管理菜单”抽屉拥有独立的顺序游标页栈，固定每页 20 条，分页条位于菜单行下方；它不与页面菜单选择器共享游标；
- 上述下拉集合不显示总数、页码、任意跳转或 page size；也不得自动请求到 `nextCursor=null` 来伪装“全量”。管理抽屉及表格集合继续使用显式固定 20 条分页。

可执行观察：分别存在 21 个 eligible 经营入口或 21 份菜单时，第 21 项可以通过下拉弹层滚动到达；切换搜索词、经营入口或重新打开管理抽屉后候选积累回到起点，同一查询内无重无漏。

## 4. 销售分区与销售项工作台

### IA-SM-SECTION-001 销售分区列表

销售分区是对客菜单结构，不能用商品分类或“全部/未分区”虚拟节点代替。

| 位置      | 草稿状态                                                     | 前台状态       |
| --------- | ------------------------------------------------------------ | -------------- |
| 分区名称  | 左侧；名称后紧跟数量，例如“主食 4”                           | 同左，整行只读 |
| 行末“…”   | `上移 / 下移 / 重命名 / 删除`                                | 不显示         |
| 上移/下移 | 第一项禁用上移，最后一项禁用下移；完成后以服务端读回顺序为准 | 不适用         |
| 新增分区  | 列表下方普通按钮                                             | 不显示         |

不提供拖动手柄，也不提供独立“调整分区顺序”按钮。

桌面工作区左侧分区导航使用比上一版约四分之一更窄的列宽；名称与数量左对齐。选中行使用与商品数模块一致的浅色主色背景、主色边界和左侧主色强调线，未选中行保留容器背景，不使用整行深色实底。

### IA-SM-ITEM-LIST-001 销售项表

#### 草稿菜单列

| 列       | 内容                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 菜单商品 | 展示图及始终可见的图片来源/状态文字、销售项展示名、商品编码；名称与编码分两行，名称可打开编辑抽屉 |
| 挂牌价   | 挂牌价与商品默认价相等时只显示挂牌价；不等时显示“菜单 / 默认”两种价格；按规格销售时每个规格一行   |
| 商品形态 | 仓内中文业务名，例如“普通销售商品 / 按规格管理商品 / 称重销售商品 / 商品型套餐 / 服务、费用商品”  |
| 销售规格 | 具体规格名称，每个规格一行；无规格时显示“无规格”                                                  |
| 销售约束 | 适用时显示起售量、订购倍数；不适用时显示“不适用”                                                  |
| 操作     | 行末“…”只有上移、下移；销售项名称已经是编辑入口，不重复放编辑或移除                               |

草稿只定义菜单内容，**不显示库存状态或人工沽清列**。

#### 前台菜单列

| 列                                      | 内容                                                                             |
| --------------------------------------- | -------------------------------------------------------------------------------- |
| 菜单商品 / 挂牌价 / 商品形态 / 销售规格 | 已发布内容，只读，挂牌价位于第二列；按规格销售时每个规格及其已发布挂牌价各占一行 |
| 库存状态                                | 独立事实：库存可售、自动不可售或不适用；只读                                     |
| 销售状态                                | 独立事实：正常销售或已沽清；可点击，打开 IA-SM-SALE-STATE-001                    |

前台菜单不显示“操作”列或“查看”按钮。销售项名称打开 IA-SM-ITEM-DETAIL-001。
库存状态与销售状态永远是两列、两个事实，不合成“可售/不可售”布尔。

#### 分页与集合边界

- 草稿与前台销售项采用与商品管理相同的 **Cursor** 集合和共享分页能力，不把全量成员取回后在浏览器切片；
- 固定每页 20 条；分页控件位于表格下方，只显示“上一页 / 第 N 页 / 下一页”，只允许沿 owner 返回的下一游标顺序前进或返回已访问页；不提供任意页跳转、总数文案或每页条数切换；
- 切换经营入口、菜单、销售分区或前台/草稿模式时清空已访问游标并回到第一页；同一范围内前后翻页不重复、不遗漏；
- 可执行观察：当一个销售分区有 21 个销售项时，第一页显示 20 条且“下一页”可用；进入第二页后显示第 21 条、“上一页”可用而“下一页”禁用。

一致性基线来自当前商品管理工作台：`CatalogWorkbenchItemList` 使用共享 `CursorPagination`，`useCatalogWorkbenchReadModel` 固定 `pageSize=20`，共享控件只允许顺序游标前进和返回已访问页。销售菜单不得另造页码跳转或可调 page size。

#### 对客顺序

- 销售项顺序是对客菜单顺序，因此草稿的每行末尾必须提供上移/下移；
- 第一项禁用上移，最后一项禁用下移；
- 页面不使用拖拽作为唯一或主要排序方式；
- 排序后以权威读回结果刷新列表，不只依赖本地视觉交换。

## 5. 添加、编辑与查看销售项

### IA-SM-ADD-001 添加商品到菜单抽屉

触发按钮位于草稿工作区标题行，紧跟在“正在编辑草稿，保存后仍需更新到前台”右侧。

| 区域       | 控件与状态                                               |
| ---------- | -------------------------------------------------------- |
| 标题       | “添加商品到菜单”；副文案固定复述目标销售分区             |
| 左侧       | 完整商品分类树；支持逐级展开/收起；分类只用于筛选        |
| 右侧候选   | 商品名称、编码、中文商品形态、所属分类、默认价格、选择框 |
| 已编入提示 | 可显示“当前菜单已有 N 个销售项”，但仍保持可选            |
| 加入       | 每次选择都会新建独立销售项；不因商品已存在而禁用         |
| 空分类     | 保留完整树节点，候选区显示“该分类暂无可编入商品”         |

同一商品可以在不同分区或同一分区重复出现。每次加入都形成独立销售项，可以分别选择销售规格、展示、价格和顺序。

右侧候选是服务端关键词/分类过滤的 Cursor 集合，固定每页 20 条；候选区下方复用商品管理同款 `上一页 / 第 N 页 / 下一页`。切换分类、关键词、经营入口或菜单时清空候选页栈并回到第一页；勾选状态按稳定商品候选 identity 保留，但已不属于当前查询的隐藏项不能被静默提交。存在 21 个候选时，第 21 项必须可经下一页找到并加入；禁止自动抽干、前端全量切片或把“当前菜单已有 N 个销售项”当成禁选条件。

### IA-SM-ITEM-001 编辑销售项抽屉

抽屉只编辑菜单定义，不展示库存、正常销售或人工沽清。

抽屉标题右侧同时显示“删除销售项”和“关闭”。删除只移除当前草稿中的这个销售项，
必须经过确认；它不删除商品，也不影响同一商品形成的其他销售项。

表单固定顺序：菜单展示名称 → 销售内容/规格与适用的挂牌价 → 适用时的起售量与订购倍数 → 展示图片。

#### 商品形态适配

| 中文商品形态   | 销售内容与挂牌价                                                                                                                                      | 起售量/订购倍数                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 普通销售商品   | 显示“该商品无规格，直接销售该商品”；公共区维护挂牌价并对照商品默认价                                                                                  | 显示                                                       |
| 按规格管理商品 | `[Dexter 对 v2s 的产品收窄]` 规格复选表：规格名称、规格编码、状态、商品默认价、菜单挂牌价；菜单挂牌价逐规格可编辑，至少选择一项；不再显示公共挂牌价区 | 显示                                                       |
| 称重销售商品   | 显示“按称重数量销售”，不伪造规格或 SKU；公共区按有效销售单位维护挂牌价                                                                                | 当前不显示；现有两个约束键按“份”定义，不能静默改成重量语义 |
| 商品型套餐     | 当前按套餐整体销售；组成内容不在菜单里重编；公共区维护挂牌价                                                                                          | 显示                                                       |
| 服务、费用商品 | 显示“该商品无规格，直接销售该商品”；公共区维护挂牌价                                                                                                  | 显示                                                       |

界面使用“规格/规格编码”，不向用户暴露 `SKU`、shape key 或原始枚举。目录后来新增规格不会自动进入已发布销售项。

#### 展示图片（表单末尾）

| 控件/状态           | 行为                                                                |
| ------------------- | ------------------------------------------------------------------- |
| Radio：沿用商品图片 | 默认；预览当前商品主图，不复制出另一份编辑区                        |
| Radio：单独设置     | 展开菜单图片编辑区                                                  |
| 菜单图片编辑区      | 与商品图片一致：上传、替换失败重试、设为主图、上移、下移、删除      |
| 数量与大小          | 复用商品图片规则：1 张主图 + 最多 5 张附图，单张不超过 2 MB         |
| 校验                | 上传中不能保存；失败图片明确重试/删除；排序后立即显示新的主图与顺序 |

### IA-SM-ITEM-DETAIL-001 前台销售项详情抽屉

点击前台菜单中的销售项名称打开详情。详情是只读信息面，不复用编辑表单的 disabled 状态。

| 详情区域     | 展示内容                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------- |
| 标题摘要     | 销售项展示名、商品编码、中文商品形态                                                                                 |
| 菜单定义     | 展示名称；按规格商品用只读规格价格表展示已开放规格、规格编码、商品默认价和菜单挂牌价；无规格商品展示销售内容与挂牌价 |
| 销售约束     | 适用时展示起售量、订购倍数；称重销售商品展示“不适用”及原因                                                           |
| 展示图片     | 直接展示当前对客图片及“沿用商品图片/单独设置”的结果，不展示 Radio、上传或排序控件                                    |
| 当前销售事实 | 库存状态与人工销售状态分成两个只读区块，不合并成一个“不可售”                                                         |

抽屉只有“关闭”。没有保存、删除、编辑、上传、复选框、Radio 或 disabled 输入框。

### IA-SM-SALE-STATE-001 正常销售 / 人工沽清确认弹窗

只从**前台菜单列表的销售状态**触发，不进入销售项编辑抽屉。

| -------- | ----------------------------------------------------------------------- |
| 正常销售 | 单选“保持正常销售 / 设置为人工沽清”；选择沽清后原因必填                 |

## 6. 菜单级局部界面

### IA-SM-MANAGE-001 管理菜单抽屉

- 显示当前经营入口下全部菜单；
- 每行按列显示菜单名、草稿状态、经营入口、菜单时段和启停状态；菜单时段独立来自菜单摘要的 `draftSchedule`；
- 每行提供启用/停用开关；停用只让该菜单不再参与当前经营入口候选，不影响继续编辑草稿或更新到前台；
- 每行提供复制、改名、归档；复制后创建“原菜单名 副本”，并自动选中新副本进入后续编辑；
- 抽屉标题右上角提供“新建菜单”；点击后打开 Modal 输入菜单名称并提交，不从页面直接打开创建抽屉；
- `[Dexter 2026-09-01 裁定]` 复制基线为源菜单当前草稿，复制销售分区/销售项及顺序、商品与规格选择、展示覆盖、挂牌价、销售项约束和菜单时段；新副本是独立草稿，默认停用；不复制发布版本/快照/记录、库存状态、人工沽清及原因或原菜单的启用关系；
- 不提供“切换”“设为当前”“替换正在生效菜单”；
- 需要查看另一份菜单时，关闭抽屉后使用页面菜单选择器。

管理菜单抽屉中的菜单表采用独立 Cursor 分页；创建、复制、归档或改名成功后以 owner 权威读回刷新当前查询。若当前页因归档变空且不是第一页，回退到上一已访问页；不得在前端维护一份所谓完整菜单数组。页面菜单选择器自身通过弹层滚动按 owner `nextCursor` 增量加载，不显示页码，也不与管理抽屉共享游标。

### IA-SM-LOG-001 操作记录

操作记录是当前页面的一种模式，不是诊断台。

| 列     | 内容                                                             |
| ------ | ---------------------------------------------------------------- |
| 时间   | 操作发生时间                                                     |
| 操作   | 例如“更新堂食菜单到前台”“修改午市套餐生效时段”“人工沽清凯撒沙拉” |
| 结果   | 成功 / 失败及简短失败原因                                        |
| 操作人 | 门店用户姓名或角色显示名                                         |

无“查看与排查”、无第 2–6 步链路、无终端状态推演。

操作记录是独立 **Cursor** 集合，复用商品管理同款顺序游标分页控件；固定每页 20 条，只显示“上一页 / 第 N 页 / 下一页”。切入“操作记录”模式时清空已访问游标并回到第一页。
可执行观察：有 21 条记录时，第一页显示 20 条且可进入第二页；第二页显示第 21 条且不可继续前进。不得先取固定条数或全量记录后在前端假分页。

`[Dexter 2026-09-01 裁定]` 操作记录模式带经营入口上下文时，记录集合包含该菜单的菜单级记录（`channel_ref IS NULL`）以及当前经营入口的渠道级记录。菜单级操作作用于菜单整体，所以在各经营入口记录中均可见；本批不另建菜单级操作记录入口。切换经营入口、菜单或模式仍按上述规则清空该日志 Cursor 并回到第一页。

## 7. 核心用户路径

### FLOW-01 编排草稿

选择经营入口 → 选择菜单 → 草稿菜单 → 选择销售分区 → 添加商品 → 编辑销售规格/价格/展示 → 行末“…”排序 → 保存。

### FLOW-02 同一商品重复编入

在“主食”选择米饭 → 加入并选“大份” → 再次打开添加商品 → 米饭仍可选 → 再加入并选“小份” → 两个销售项独立排序。

### FLOW-03 更新到前台

草稿菜单 → 更新到前台 → 核对变更与阻断 → 确认 → 看到“本系统已生成前台菜单” → 返回前台菜单。

### FLOW-04 人工沽清与恢复

前台菜单 → 点击销售状态“正常销售” → 选择人工沽清并填写原因 → 确认；恢复时再次点击“已沽清” → 选择恢复正常销售 → 确认。

### FLOW-05 多菜单并列生效

选择菜单 A → 生效与时段 → 启用；选择菜单 B → 生效与时段 → 也启用。页面不要求关闭 A，不显示唯一“当前生效菜单”。

## 9. 可访问性与焦点

- 分段控件、下拉选项、树节点、Radio、复选框和“…”菜单均可键盘操作；
- 行末菜单的上移/下移是完整排序方式，不依赖拖拽；
- 弹窗/抽屉打开后焦点进入标题或首个控件，关闭后回到触发按钮；
- 禁用上移/下移时同时提供禁用状态，不只用颜色；
- 库存状态、销售状态、发布结果都必须有文字，不以红绿颜色代替含义。

## 11. Dexter 本轮可直接确认什么

请在可操作原型中按 FLOW-01 至 FLOW-05 实际点击，并确认：

1. 不离开一个页面，是否足以完成菜单日常任务；
2. 草稿编排是否只出现菜单定义，前台菜单是否才出现库存与销售状态；
3. 分区和销售项的行末上移/下移是否符合 V2S 现有操作习惯；
4. 普通、按规格、称重商品的销售项编辑是否符合各自业务形态；
5. 同一商品重复编入、多菜单同时启用是否都没有被界面错误阻断；
6. 销售项名称是否足够承担编辑入口，行末是否确实只剩上移/下移；
7. 删除销售项放在编辑抽屉标题区是否顺手，确认文案是否足以避免误删商品或其他销售项；
8. 管理菜单中的启用/停用、复制、改名、归档是否符合门店日常操作，停用后是否仍应允许编辑与更新到前台；
9. 复制当前草稿与菜单时段后，是否清晰呈现新副本已被选中且默认停用，并且没有把发布记录、库存、人工沽清或原菜单启用关系带入副本；
10. 按规格管理商品是否应只在规格行逐项改菜单挂牌价并取消公共挂牌价区，无规格商品继续使用公共挂牌价区；
11. 前台菜单去掉操作列后，点击销售项名称查看详情是否足够直接；
12. 前台详情是否已经是清晰的只读信息布局，而不是一组不可编辑表单；
13. 草稿、前台销售项和操作记录是否与商品管理一样使用“上一页 / 第 N 页 / 下一页”的固定 20 条顺序分页，并在切换范围时正确回到第一页；
14. 操作记录是否已经回到普通记录，不再承担诊断工作台职责。

Dexter 确认本 IA 前，不开始 implementation-facing 技术详设或实施计划。
