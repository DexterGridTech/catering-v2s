# 商品库观察问题整改设计附录

本附录由 Dexter 于 2026-08-26 对真实工作台体验的直接裁定触发，覆盖与既有设计冲突的局部呈现规则；
其余正式需求、Journey、IA、implementation design 与 serial plan 保持有效。

## A-01 商品父行展开入口

有规格的父商品将唯一的展开/收起按钮置于**商品名称左侧、同一行**。不再显示独立的 40px 展开工具列；
选择列仍只服务批量选择。无规格父商品不显示该按钮，规格子行不进入父商品批量选择。

这是位置和表格形态的更正，不改变 `childrenColumnName`、受控 expanded keys、父级范围内懒读 SKU、loading/error/
继续加载子行或 row key。SKU 子行保持相对父行 24px 缩进、极浅层级底色与连续层级引导。

## A-02 生命周期事实与体验 seed

商品与 SKU 各自的生命周期状态继续由 catalog owner 原样返回，前端不得合并、覆盖或合成另一种“有效状态”。
体验 seed 的完成配置父商品通过公开 lifecycle command 转为启用；草稿父商品与启用 SKU 仅可作为明确的中间/边界 fixture，
不得成为默认体验数据。

## A-03 引用关系与作废原因

详情分开显示“商品关联”和“当前不能作废的原因”。后者是 catalog owner 汇总的 read model，必须包括 catalog 自有
阻断和 inventory owner 的库存对象/用料阻断；不显示 UUID、raw kind、内部 reference 或 JSON。关联为空时只写
“没有与其他商品的关联”，不得与笼统“有依赖”并列造成矛盾。

`canVoid=false` 必须随 read model 返回至少一条非空业务原因及正计数；库存对象与用料分别保留
`INVENTORY_TARGET` 和 `INVENTORY_BOM` 事实类型，不能由 item/SKU 投影层改写。规格作废成功后，前端只可采用
响应中与请求规格精确匹配、目标为“已作废”、版本与完整限制事实均存在的 owner transition；缺失、重复或畸形响应
只能提示重新读取，绝不在本地伪造“已作废”或“不可作废”状态。

## A-05 库存扣减与用料的配置对象导航

查看与编辑不是两套库存配置模型：它们只是在同一组库存/BOM 节点上的不同操作状态。因此两处必须复用同一个
配置对象导航呈现件，统一对象键、当前项回退、业务名称解析、层级缩进、键盘行为和选中态；详情正文可以各自
按只读或可编辑职责呈现。

- 商品项显示商品名称；规格项显示规格名称与规格编码；点单选项项显示选项值名称与所属选项名称。名称取自已
  读入的商品详情事实，不能另发请求，也不得把编码当作用户主名称。
- 导航是局部定位，不是保存、删除或危险操作。选中态只用浅色背景、左侧指示和清晰焦点，不得使用整块主按钮。
- 规格与点单选项相对商品项缩进；长名称截断时必须有 Tooltip。切换仅改变本地当前项，绝不改写库存/BOM 草稿。

## A-06 编辑内维护商品元数据

编辑商品时，用户从任一编辑区段打开“维护商品元数据”，父编辑抽屉必须保持打开；元数据配置仅作为该编辑面的
一层子任务面。子任务关闭后，焦点回到原维护控件，当前区段、滚动位置、校验结果和未保存的商品编辑内容保持不变。

该路径不保存、读取或恢复任何“编辑转配置”的过渡草稿：不得建立 `returnToEdit`、恢复令牌或工作台“继续编辑”入口。
异常关闭或刷新后的整单草稿恢复仍是独立的防意外丢失机制，不能被编辑内元数据操作触发、改写或用作其返回方式。
