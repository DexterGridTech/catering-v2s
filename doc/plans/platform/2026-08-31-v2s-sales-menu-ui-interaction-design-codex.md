## 1. V4 继承结论

V2S 继承 V4 的一个页面、同页模式切换、左销售分区右销售项、菜单选择器和局部抽屉。
V4 没有证明更优，或与 V2S 已裁口径冲突的交互，不照搬。

| 任务 | V4 当前实现事实 | V2S 处理 |
| --- | --- | --- |
| 页面结构 | 只有一个菜单页面 | 原样继承 |
| 前台/草稿/记录 | 同页分段切换 | 原样继承，记录改称“操作记录” |
| 多菜单 | 用菜单选择器切换工作对象 | 原样继承；选择不代表唯一生效 |
| 分区与销售项 | 左分区、右销售项 | 原样继承 |
| 添加与编辑 | 当前页打开局部抽屉 | 原样继承 |
| 分区排序 | V4 用拖拽 | 不继承；按 Dexter 裁定改为行末“…”上移/下移 |
| 销售项排序 | V4 用名称旁拖拽手柄 | 不继承；按 Dexter 裁定改为最后一列“…”上移/下移 |
| 人工沽清 | V4 页面没有证明列表交互，只有后端语义证据 | 不能从 V4 推导；按 Dexter 裁定放在前台列表状态操作 |
| 发布记录 | 普通平面记录 | 继承简单形态，不扩展成诊断工作台 |
| 重复编入 | V4 黑盒证明同商品可在同分区或跨分区形成多条销售项 | 继承，并按 Dexter 裁定允许各销售项独立选择规格 |
| 商品分类 | V4 添加抽屉有分类树 | 继承完整树，不截断成示例列表 |
| 商品形态 | V4 添加候选没有展示 | V2S 补齐；仓内商品 IA 已把形态裁为关键可见信息 |

无论使用哪种排序控件，V4“保存后必须以服务端读回顺序为准”的教训继续保留。

V4 核验来源：`catering-server-v4/frontend/apps/catering-operations-admin/src/resources/sales-channel-menus/components/` 下的
`MenuSectionTree.tsx`、`MenuSalesItemTable.tsx`、`BatchAddSalesItemsDrawer.tsx`、`PublicationRecordList.tsx`，
以及 `catering-server-v4/acceptance-tests/backend/run-v4-sales-channel-menu-blackbox.mjs`。

## 2. 唯一页面的实际操作顺序

```text
全局门店已选定
  → 选经营入口
  → 选 前台菜单 / 草稿菜单 / 操作记录
  → 选当前查看或编辑的菜单
  → 在左侧选销售分区
  → 在右侧处理销售项
```

菜单页标题旁不重复显示门店名称。门店变化只由运营后台全局上下文驱动。

## 3. 草稿菜单交互

### 3.1 销售分区

每行结构固定为：

```text
分区名称  数量                                      …
```

- 数量紧跟名称；
- “…”菜单：上移、下移、重命名、删除；
- 第一行上移禁用，最后一行下移禁用；
- 无拖拽手柄，无“调整分区顺序”按钮。

### 3.2 销售项表

草稿列固定为：

```text
菜单商品 | 商品形态 | 销售规格 | 挂牌价 | 销售约束 | 操作
```

“操作”列的“…”菜单只有上移、下移。销售项名称已经打开编辑抽屉；移除放在编辑抽屉标题区的“删除销售项”，不在列表重复。

草稿销售项表复用商品管理的顺序游标分页能力，分页条位于表格下方；固定每页 20 条，只显示“上一页 / 第 N 页 / 下一页”。切换经营入口、菜单或销售分区后清空已访问游标并回到第一页。

工作区标题右侧按以下顺序排列：

```text
正在编辑草稿，保存后仍需更新到前台    [添加商品到菜单]
```

### 3.3 添加商品

- 左侧展示完整商品分类树，节点可展开/收起；
- 右侧候选必须显示中文商品形态；
- 已经在菜单里的商品仍可勾选，只用副文案说明已有销售项数量；
- 每次加入产生一个新销售项，不做商品级去重；
- 加入后在销售项抽屉选择销售规格、展示、价格和约束。

候选区提供服务端关键词搜索，并在列表下方使用商品管理同款顺序游标分页：固定 20 条、只显示“上一页 / 第 N 页 / 下一页”。切换分类或关键词回到第一页；勾选按稳定候选 identity 保存，隐藏候选不静默提交。21 个候选时，第 21 个必须能通过下一页找到，禁止后台自动抽干全部页或浏览器全量切片。

### 3.4 编辑销售项

抽屉标题右侧为“删除销售项 / 关闭”。删除需要确认，只移除当前草稿销售项，不删除商品或其他同商品销售项。

表单顺序：展示名称 → 销售内容/规格与适用挂牌价 → 适用约束 → 展示图片。

| 商品形态 | 销售内容与挂牌价 | 约束区 |
| --- | --- | --- |
| 普通销售商品 | 无规格说明；公共区维护挂牌价与商品默认价 | 起售量、订购倍数 |
| 按规格管理商品 | 规格表逐行选择规格，并逐行维护菜单挂牌价与对照商品默认价；不显示公共挂牌价区 | 起售量、订购倍数 |
| 称重销售商品 | 按称重销售说明；公共区按 Catalog 有效销售单位维护挂牌价，单位为只读结构化商品事实 | 当前不显示；现有两个约束键不能从“份”静默改成重量语义 |
| 商品型套餐 | 直接销售套餐说明；公共区维护挂牌价 | 起售量、订购倍数 |
| 服务、费用商品 | 无规格说明；公共区维护挂牌价 | 起售量、订购倍数 |

抽屉内不显示库存或人工沽清。

展示图片放在最末：Radio 选择“沿用商品图片 / 单独设置”。选择单独设置后，出现与商品图片一致的上传、替换失败重试、设主图、上移、下移和删除。

称重销售商品的单位来自 Catalog owner 的结构化 `salesUnit`（单位引用、编码、名称、维度、精度），只读展示，不能在菜单编辑抽屉中新增、修改、删除或通过 `unitLabel` 输入覆盖；保存请求不携带单位。草稿读取当前 Catalog 单位，发布后的前台读取发布时冻结的单位快照。

## 4. 前台菜单交互

前台列固定为：

```text
菜单商品 | 商品形态 | 销售规格 | 挂牌价 | 库存状态 | 销售状态
```

- 不显示“操作”列或“查看”按钮；点击销售项名称打开查看详情抽屉；
- 库存状态只读，由库存事实派生；
- 销售状态显示“正常销售”或“已沽清”，点击后打开确认弹窗；
- 两个状态绝不合并；
- 前台内容只读，不允许排序或编辑挂牌价。

查看详情抽屉使用标题摘要、只读说明项、只读规格价格表、销售约束、对客图片和两个独立销售状态区块。
抽屉不得渲染 disabled 输入框、复选框、Radio、上传、排序、保存或删除；唯一动作是“关闭”。

前台销售项表与草稿使用相同的商品管理式顺序游标分页，但前台/草稿各自是独立范围；切换模式后清空已访问游标并回到第一页。

销售状态弹窗用 Radio 让用户明确选择正常销售或人工沽清。设置沽清时原因必填；恢复时二次确认。弹窗不能恢复库存自动不可售。

## 5. 多菜单与时段

菜单选择器只回答“我现在在看/编辑哪份菜单”。

“生效与时段”抽屉回答：

- 这份菜单是否在当前经营入口启用；
- 全天还是每日时段；
- 若为每日时段，开始与结束时间。

抽屉固定提示：同一经营入口可同时启用多份菜单，实际使用由销售端判断。

“管理菜单”处理新建、启用/停用、复制、改名、归档。停用不阻断编辑或更新到前台；复制生成“原菜单名 副本”。`[Dexter 2026-09-01 裁定]` 复制当前草稿定义与菜单时段，新副本为独立草稿且默认停用；发布记录、库存、人工沽清和原菜单启用关系不复制。不得出现“切换”“设为当前生效”或其他互斥暗示。

经营入口卡片、菜单选择器和管理菜单行都必须让第 21 项可见可选，但不得自动拉完全部游标页：

- 卡片组下方使用商品管理同款“上一页 / 第 N 页 / 下一页”；换页不自动改变当前入口；
- 菜单选择器是服务端可搜索下拉，面板底部使用同款顺序分页；搜索词变化回到第一页，当前选中菜单始终在选择器中可辨认；
- 管理菜单抽屉在菜单行下方使用独立顺序分页；其页栈不与选择器共享；
- 三处均固定 20 条，不显示总数、不跳页、不调 page size。经营入口或查询 identity 变化即清空对应已访问游标。

## 6. 发布与操作记录

“更新到前台”继续是准确的发布动作。成功只说明本系统已生成前台菜单，不代表终端已经获取。

“操作记录”是普通表格：

```text
时间 | 操作 | 结果 | 操作人
```

不提供记录详情、发布与可见性排查、第 2–6 步诊断链路或终端状态推演。
操作记录独立复用商品管理式顺序游标分页；固定每页 20 条，只显示“上一页 / 第 N 页 / 下一页”，切入该模式时清空已访问游标并回到第一页。
`[Dexter 2026-09-01 裁定]` 按经营入口查看时，操作记录同时显示该菜单的菜单级记录（`channel_ref IS NULL`）与当前经营入口的渠道级记录；菜单级操作影响菜单整体，因此在各入口记录中均可见。本批不另建菜单级操作记录入口。

集合可达性属于同一单页交互的组成部分：21 个经营入口、21 份菜单和 21 个候选分别通过各自显式顺序分页到达，不能以常见小数据量隐藏第 21 项，也不能以“自动加载全部”制造无界请求。

## 7. 控件状态清单

| 控件 | 正常 | 禁用/隐藏 | 失败与恢复 |
| --- | --- | --- | --- |
| 添加商品到菜单 | 草稿模式且已选分区 | 前台/记录隐藏；无分区禁用 | 候选加载失败保留分类树并重试 |
| 分区“…” | 草稿显示 | 前台隐藏 | 排序失败回到权威读回顺序并提示 |
| 销售项“…” | 草稿显示 | 前台隐藏；名称进入详情 | 排序失败回到权威读回顺序并提示 |
| 更新到前台 | 草稿可发布 | 入口停用或校验失败禁用 | 展示明确阻断原因 |
| 销售状态 | 前台可点击 | 草稿不显示 | 保存失败保持弹窗和已填原因 |
| 单独设置图片 | 草稿可选 | 前台只读 | 上传失败可重试/删除 |
| 规格复选 | 仅按规格管理商品显示 | 其他形态不显示 | 无可选规格时阻断保存并说明原因 |

## 8. 31 条需求验收脚本

1. 页面标题区域没有门店名称，确认门店仅来自全局上下文；
2. 分区行无拖拽，行末“…”提供上移/下移；
3. 分区数量紧跟分区名称，而不是贴在行最右侧；
4. 页面不存在“调整分区顺序”；
5. 草稿提示右侧存在“添加商品到菜单”；
6. 人工沽清只出现在前台菜单销售项的销售状态操作中，不出现在编辑抽屉；
7. 打开销售项编辑，确认没有库存或人工沽清信息；
8. 打开称重销售商品，确认不展示按“份”定义的起售量与订购倍数；
9. 图片位于表单末尾，先选“沿用商品图片/单独设置”，选择单独设置后可上传和排序；
10. 分别打开按规格与无规格商品，确认销售规格选择随商品形态变化；
11. 草稿销售项行末“…”提供上移/下移；
12. 连续两次添加同一商品，第二次仍可选，并形成可独立选规格的销售项；
13. 添加抽屉展示完整商品分类树，分类只用于查找商品；
14. 添加抽屉每个候选项展示中文商品形态；
15. 草稿与前台销售项列表都有商品形态列；
16. 草稿菜单没有库存状态和人工沽清列；
17. 页面不存在“查看发布与可见性排查”入口或第 2–6 步诊断面板；
18. 操作记录仅展示时间、操作、结果和操作人；
19. 切到前台菜单，点击“正常销售/已沽清”完成状态选择、沽清原因或恢复确认；
20. 菜单选择器只改变当前查看/编辑对象；两份菜单可同时启用，不要求互斥；
21. 点击销售项名称进入编辑抽屉；行末“…”中不存在重复的“编辑”；
22. 销售项行末“…”中不存在“移除”；
23. 编辑销售项抽屉标题区有“删除销售项”，删除前明确确认只影响当前草稿销售项；
24. 管理菜单的每行都有启用/停用开关；停用后仍能进入编辑并点击“更新到前台”；
25. 点击“复制”后自动生成并选中“原菜单名 副本”；
26. 打开“生效与时段”，确认启停状态只读，且菜单选择、编辑、发布与启停互不替代；
27. 打开按规格管理商品，确认每个规格行都有可编辑的菜单挂牌价；
28. 按规格管理商品没有公共挂牌价区；普通或称重等无规格商品仍有公共挂牌价和商品默认价；
29. 前台菜单表头没有“操作”，每行没有“查看”，点击销售项名称打开详情；
30. 前台详情只包含只读信息、只读表格和状态区块，没有任何 disabled 表单控件或编辑动作；
31. 草稿、前台销售项表和操作记录表都复用商品管理式分页：固定每页 20 条，只能上一页/下一页并显示当前第 N 页，不显示总数、不允许任意页跳转或调整每页条数；切换经营入口、菜单、分区或模式后回到第一页。

任一项不成立，IA 原型即未完成本轮修复。
