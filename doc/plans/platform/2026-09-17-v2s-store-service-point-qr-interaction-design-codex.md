## 1. 全局交互约束

1. 页面用户可见的实体名称只有“区域”“桌台”“扫码点”“二维码配置”；“服务点”只用于技术说明，不用于标题、按钮、列表标题、抽屉标题、空态或帮助文本。
2. “新建区域”永远属于左侧区域列表头部；它不随当前区域选择变化，也不放进页面全局工具栏。
3. 右侧列表只有在选中区域后才出现新增动作：桌台区显示“新建桌台”，扫码区显示“新建扫码点”。未选中区域时右侧只显示“请选择区域”，没有新增按钮。
4. 右侧列表标题与动作必须使用同一类型映射：`桌台区 → 桌台 / 新建桌台`，`扫码区 → 扫码点 / 新建扫码点`。
5. 主页面的“二维码配置”只显示只读信息和“编辑”按钮；开关和渠道选择只能在二维码配置 Drawer 中编辑。
6. 新建和编辑抽屉的所有 dirty、关闭确认、Esc、遮罩和提交中锁定由 `useDrawerFormLifecycle` 统一管理。子控件不得维护自己的 dirty 状态，也不得自行向用户显示“请先保存”。
7. 详情抽屉呈现只读业务事实，不使用不可编辑的 Form 控件来伪装详情；编辑抽屉才承载真实 Form 控件。
8. 仅桌台的图片复用现有资产链路；扫码点不提供图片字段或图片上传；扩展字段复用现有宿主机制；二维码最终 URL 不作为对象字段保存。
9. 区域列表和桌台/扫码点列表沿用销售菜单页面的两个列表模式：左侧整行选中与行末“…”操作，右侧表格最后一列“…”操作；不新增拖拽、独立选中模型或全局排序入口。

### 主工作台状态矩阵

| 状态 | 左侧区域区 | 右侧从属区 | 可见动作 |
| --- | --- | --- | --- |
| loading | 页面 loading | 不渲染旧集合 | 无新建动作，避免对未稳定 scope 操作 |
| 区域读取失败 | 失败文案 + 重试 | 不读 | 只有真实重试；不显示新建区域，除非 owner 明确允许在无列表事实下创建（当前不自定） |
| 区域为空 | 空态 | “请选择区域” | 区域头部显示“新建区域”，右侧无新建动作 |
| 无选择 | 区域列表 | “请选择区域” | 仅“新建区域” |
| 选中桌台区 | 当前区域高亮 | 桌台集合/空态/失败 | “新建区域”+“新建桌台” |
| 选中扫码区 | 当前区域高亮 | 扫码点集合/空态/失败 | “新建区域”+“新建扫码点” |
| 只读 | 列表可读 | 列表可读 | 隐藏所有新建/编辑/作废动作 |
| 未开通 | 共享未开通 surface | 不发业务列表请求 | 复用上一批 disabled surface，不显示新建动作 |

### 销售菜单式列表交互

两个列表的结构、选中态和排序入口直接参考当前销售菜单页面，不另造新的列表习惯：

| 本页列表 | 销售菜单对应列表 | 交互规则 |
| --- | --- | --- |
| 区域列表 | 销售分区列表 | Card 头部放“新建区域”；每行是整行可点击的 master 选择按钮；选中行使用浅色主色背景、左侧强调线和 `aria-current`；行末“…”菜单放编辑、上移、下移及其他已批准的区域操作。 |
| 桌台/扫码点列表 | 销售项表 | 右侧使用表格；名称为可操作文本进入详情；最后一列固定为“…”操作菜单，放上移、下移、编辑、作废等已批准动作；不引入行拖拽或额外的独立行选中态。 |

排序菜单的具体边界与销售菜单一致：第一条“上移”禁用，最后一条“下移”禁用；排序按相邻一位移动；排序请求完成前锁定同一行的重复排序动作；失败后以服务端权威顺序恢复并显示准确反馈。区域列表的 master 选中与排序动作相互独立，点击“…”不改变当前选中区域；从属列表的上下文始终由当前区域决定。

顺序不属于任何创建/编辑 Drawer 的表单字段。创建或编辑抽屉只维护对象资料；区域、桌台和扫码点的顺序统一通过列表行末“…”菜单中的“上移/下移”操作维护。

## 4. OPS-SPQ-06：二维码配置 Drawer 线框

```text
┌ 编辑二维码配置                                         [×] ┐
│ 是否启用二维码下单        [ 开关 ]                         │
│                                                            │
│ 门店渠道                  [ 请选择门店渠道 ▼ ]             │
│ 说明：开启二维码下单后需要选择门店渠道                     │
│                                                            │
│ 当前配置由门店保存；候选渠道与二维码生成按服务端规则处理  │
├────────────────────────────────────────────────────────────┤
│                                  [取消]          [保存]      │
└────────────────────────────────────────────────────────────┘
```

- 未开启时渠道可以为空；开启时保存必须选择渠道。已存在的渠道值按 owner readback 展示，不由页面擅自清空。
- 候选列表在 Drawer 内使用 bounded read；URL 规则为空或不合法的渠道仍可选、可保存，生成位置显示“暂未生成二维码”。
- Drawer 关闭、Esc、遮罩、脏状态确认和提交中锁定统一由 `useDrawerFormLifecycle` 管理；开关和渠道选择控件不自行弹出“请先保存”。

```text
│     ├─ 关闭/开启二维码下单
│     ├─ 读取并选择门店渠道
│     └─ 保存后刷新主页面配置区与二维码生成投影
├─ 区域列表头部
│  └─ 新建区域 → 区域 Drawer
└─ 选中区域
   ├─ 桌台区 → 桌台列表头部 → 新建桌台 → 桌台 Drawer
   └─ 扫码区 → 扫码点列表头部 → 新建扫码点 → 扫码点 Drawer
```

| 控件/动作 | 上游依赖 | 依赖改变时 | 保存/恢复 |
| --- | --- | --- | --- |
| 新建区域 | 页面已有稳定门店 scope、区域写权限 | scope/权限失败时不显示 | 保存由区域 owner 校验，成功后关闭 Drawer 并 readback；保留已有 master 选择，首次无选择时不自动选中新区域，右侧继续显示“请选择区域” |
| 新建桌台 | 已选区域且类型=桌台区、从属写权限 | 切换到扫码区或清除选择时立即消失 | 类型由当前区域带入，owner 再校验；成功后关闭 Drawer 并重读当前桌台列表，保持当前区域选择 |
| 新建扫码点 | 已选区域且类型=扫码区、从属写权限 | 切换到桌台区或清除选择时立即消失 | 类型由当前区域带入，owner 再校验；成功后关闭 Drawer 并重读当前扫码点列表，保持当前区域选择 |
| 编辑二维码配置 | 主页面二维码配置区读取成功且具备编辑权限 | 无编辑权限隐藏；读取失败不显示可编辑 Drawer | 打开 `OPS-SPQ-06`；保存由 owner 复核门店归属与四维谓词，成功后 readback |
| 二维码开关/渠道选择 | 二维码配置 Drawer 已打开；候选 bounded read 成功 | 关闭二维码时渠道可为空；候选错误显示真实错误 | 统一 Drawer dirty guard；保存后刷新主页面配置区只读信息 |
| 二维码列/详情 | 当前对象 readback、最终 URL 判定 | URL 为空/非法显示固定占位 | 不改变区域/对象存储值；配置保存后按 owner projection 刷新 |
| 任一抽屉关闭 | Foundation dirty state | dirty 时统一询问是否放弃 | 所有子控件不自行提示；提交中锁定关闭路径 |

## 10. 状态、错误与恢复线框约束

| 位置 | loading | empty | failed | disabled/不可用 |
| --- | --- | --- | --- | --- |
| 区域列表 | 列表区域 loading | “暂无区域”，头部仍有“新建区域”（仅在权限/事实允许时） | “暂时无法获取区域，请重试。” | 未开通时复用共享未开通 surface |
| 桌台/扫码点列表 | 当前标题下 loading，不保留旧区域行 | “暂无桌台”或“暂无扫码点”，头部保留对应动态新增按钮 | “暂时无法获取桌台/扫码点，请重试。” | 区域未启用时显示不可用状态，不改写存储值 |
| 二维码配置区 | 只读信息 skeleton/loading | 未选渠道按契约呈现 | “暂时无法获取二维码配置，请重试。”；“编辑”不出现 | 未开启是业务关闭，不当作读取失败；编辑在 Drawer 内完成 |
| 二维码配置 Drawer | Drawer body loading | 未选渠道按契约呈现 | 保留输入与真实错误 | 未开启允许渠道为空；不是把详情区变成 disabled Form |
| 二维码结果 | 生成中按实现可见 loading | “暂未生成二维码” | 生成失败统一为“暂未生成二维码”，不抛给候选层 | 区域/对象不可用时按需求显示边界，但不改写生成事实 |
| 抽屉 | Drawer body loading | 首次新建使用明确默认值 | 保留输入和准确 problem | 不可编辑字段使用真实 disabled/只读语义，不用一组 disabled Form 冒充详情 |

“暂未生成二维码”只覆盖 D-10/D-12 规定的生成层空/非法最终 URL 情形，不增加渠道状态导致的第四种生成阻断，也不把候选过滤扩大到 URL 规则。
