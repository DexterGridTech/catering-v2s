## Typecheck evidence and installation boundary

The first ordinary package probes exposed missing UI workspace links because
the prior CP-2 install state did not contain these five packages:

```text
render, automation: direct tsc exit 0
primitives: TS2307 @catering-v2s/ui-base-automation
test-support: TS2307 @catering-v2s/ui-base-render,
  @catering-v2s/ui-base-automation
platform-console: TS2307 all four UI package roots
```

An immutable install was first attempted without changing root manifests:

```sh
YARN_ENABLE_IMMUTABLE_INSTALLS=true \
YARN_ENABLE_HARDENED_MODE=false \
yarn install --immutable --mode=skip-build
```

It exited 1. Yarn 4.17.0 resolved the new React/RN package set, then refused
to proceed because the existing lockfile does not contain those resolutions:

```text
YN0085: + @types/react@npm:19.2.18, react-native@npm:0.86.3,
        react@npm:19.2.3, ... and 145 more.
YN0028: The lockfile would have been modified by this install,
        which is explicitly forbidden.
```

No `package.json` or `yarn.lock` was changed by this attempt. A preceding
invalid option probe (`--mode=skip-builds`) exited 1 with Yarn's usage error;
it made no repository change.

The authorized normal root install was then run from the repository root:

```sh
YARN_NODE_LINKER=node-modules yarn install
```

It exited 0 in 11.893 seconds. Yarn added the five UI workspace resolutions and
their transitive packages, updated the lockfile, and reported only the existing
`YN0086` peer-dependency warning. The `YN0028` immutable failure is retained as
the first failure; it is not treated as a successful installation.

To isolate source resolution from the stale install state, five exact,
ignored `node_modules/@catering-v2s/*` symlinks were created temporarily,
pointing only to the five new UI directories. With those links in place,
the following absolute TypeScript commands all exited 0:

```text
apps/terminal/ui/base/render                    EXIT=0
apps/terminal/ui/base/automation                EXIT=0
apps/terminal/ui/base/primitives                EXIT=0
apps/terminal/ui/base/test-support              EXIT=0
apps/terminal/ui/integration/platform-console   EXIT=0
```

These are source-resolution probes, not a claim that Yarn installation has
completed. The five symlinks were removed explicitly and each reported
`CLEANUP_OK`; no symlink remains.

The Turbo filter was parsed against the real workspace tree:

```text
yarn turbo run typecheck --filter='./apps/terminal/**' \
  --filter='!@catering-v2s/terminal' --dry=json
DRY_EXIT=0
packages=12 (7 kernel + 5 UI)
```

Turbo emitted a warning that the new UI workspace is not in the existing
lockfile. The non-dry run therefore failed inside Yarn's temporary execution
environment before the new UI tasks could execute:

```text

  Workspace 'apps/terminal/ui/base/primitives' not found in lockfile.

  workspace:apps/terminal/ui/base/automation not found in the project
TURBO_EXIT=1
```

After the normal install, the five workspace commands were rerun directly and
all exited 0. The filtered Turbo command was rerun against the same tree and
reported 12 successful tasks out of 12 (7 kernel + 5 UI), with no frontend or
library workspace in scope:
