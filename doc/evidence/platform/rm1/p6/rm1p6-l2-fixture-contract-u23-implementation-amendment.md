# U23 platform L2 fixture and browser-suite alignment

The managed platform L2 fixture must read the generated `CommercialGroupRoot` exactly as its owner edge returns it and must emit the same name/code label as platform-admin. The L2 first failure proved the fixture used `group.json.name`, while the accepted contract and generated wire expose `groupName`; the next fresh L2 run showed that it also emitted the retired full-width label `名称（编码）` while platform-admin renders `名称(编码)`. Owner commands returned 201 in both runs.

The minimal repair changes only the fixture projection to `group.json.groupName`, emits ASCII parentheses for every name/code label in both fixture producers, and adds a focused source test. The sibling joint L2 fixture does not consume the commercial-group response, but it did retain the same obsolete full-width separators and is aligned in the same repair.

The fresh browser run then proved a second, independent test-harness root: nine L2 files concurrently authenticate the same root account and mutate the same fixture, while several assertions target hidden Ant Design inputs, non-canonical bare name values, unscoped text that collides with page descriptions, collapsed QueryFilter fields, a selected workspace before its Select overlay has fully closed and persisted to the shell, or an icon-bearing navigation item's incomplete accessible name. It also exposed a fixture-level invalid mutation state: the editable GROUP role was created with an empty `pageAccessKeys`, while the real form requires an owner-catalog page selection, so the browser correctly blocked submit before any PATCH. The minimal repair serializes this shared-fixture suite, makes name/code targets consume explicit canonical labels, waits for settled workspace scope, targets the stable menu-name suffix, and makes the fixture use the real GROUP `PG-ORG-STRUCTURE` owner-catalog page key. No owner, schema, API, database, capability, or runtime policy changes are permitted. A fresh isolated L2 run is required after this repair; failed runs are evidence only.

The next fresh L2 run exposed the common QueryFilter defect: the workspace-account and invitation panels relied on the ProTable default action surface, which did not invoke their controlled `onSubmit` state transition. The same default-action pattern existed in operations-admin contract management; every other searchable ProTable already uses an explicit `searchConfig.form?.submit()` action. The minimal repair gives all three panels the same explicit submit/reset actions, preserving their existing independently owned filter state and ten-row pagination. No owner, schema, API, database, capability, or runtime policy changes are permitted. A fresh isolated L2 run is required after this repair; failed runs are evidence only.
