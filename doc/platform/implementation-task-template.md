## 为什么必须只有一份

它在建立后数小时内就漂了三份:两份写「完成之后」的分隔线用 `━━━`,
一份不用;两份写「用 RECALL **里**那份原文」,一份写「用 RECALL 那份原文」。
**这个模板的全部目的就是防漂移,而它自己先漂了。**

⚠️ 复制它是**分发**,不是重复;**改写它才是重复**。
派活时整块粘贴即可,不要为了「读起来顺」调整措辞。

## 正本(逐字复制以下代码块)

```
每进入一项之前:按该项 RECALL 走一遍。字段为空 ⇒ 停下来问。
⚠️ 走完 RECALL 是你拥有自主权的前提 —— 没走完,下面的自主权不成立。

━━ 你可以自行决定的 ━━
在**不变量全部满足**且**不违反 FORBID** 的前提下,**实现形态由你定**。
工单给的是「必须同时满足什么」,不是「必须怎么写」。
发现更好的写法就直接用,不必回来问 —— 只需在报告里**登记一行理由**:
「我选了 X 而不是 Y,因为 Z」。

━━ 必须停的四类(只有这四类)━━
1. 不变量之间**互相冲突** —— 满足这条就违反那条
2. 不变量**说不清** —— 失败条件写不出来
3. 不变量**与源码不符** —— 工单说的前提在代码里不成立
4. 满足不变量**必须动 FORBID 的东西**

⚠️ 第 2–4 类里,上游(详设 · 评审 finding · 我给的分母与数字 · 任何"权威"结论)
   都是**待验证输入**。⛔ 不因为它来自设计方或评审方就采信;**以源码为准**。

停的时候不要做这四件事:
  自己选一个"合理的"做法**绕过不变量** · 加兼容层 / fallback / TODO 绕过 ·
  缩小范围报完成 · 改业务行为去迎合门。
报告给三样:你看到的原文事实 · 两种候选理解 · 你倾向哪个及为什么。
只说"卡住了"会多走一个来回。

━━ 完成之后 ━━
1. 用 RECALL 里那份原文逐项回读:做出来的,和它写的是同一件事吗?
2. 跑相关编译与门,贴真实输出。不接受「预期会绿」。
   ⚠️ 注意解释器:scripts/check/ 下有 bash 也有 node,按 shebang 选,判红绿用退出码。
3. 声明证据档位:编译 / 静态门 / 容器 / 浏览器。⛔ 低档不得说成高档。
4. 报告里出现「全仓 / 唯一 / 零 / 只有」时,先跑搜索,把条数写进句子。
   写不出条数,就不许用这些词。
5. **凡自行决定的形态,逐条登记理由**(一行即可)。
```

## 短版(日常派活用这个)

完整版只在**第一次**或对方换新会话、对这套约定完全陌生时用一次。
**日常派活用下面这段** —— 它只内联三样在长版里最救命的东西,其余靠正本与 `RECALL` 兜。

```
工单:<路径>
本批范围:<第 N–M 项>。范围外看到也不动,报告即可。
执行纪律见 doc/platform/implementation-task-template.md,按它做。

形态由你定:不变量全部满足、不违反 FORBID 的前提下,写法你选,
不必回来问 —— 报告里登记一行「我选了 X 而不是 Y,因为 Z」。
前提是你走完了该项的 RECALL。

只有四类必须停:不变量互相冲突 · 说不清 · 与源码不符 · 满足它必须动 FORBID。
上游(含我给的数字与 finding)都是待验证输入,以源码为准。

PROOF 贴真实运行输出,不接受「预期会绿」。
当前红门清单现跑现取,不要用任何文档里的快照。
```

**为什么只留这四条内联**:
自主权是**新增的**,不内联他不会知道自己有;
四类停机是**边界**,不内联会退回「凡事都问」或「凡事自己定」;
真实输出防的是「以为跑了其实没跑」;
现跑现取防的是分发过期快照。
其余(RECALL 怎么走、报告给哪三样、证据档位)在正本里,他会去读。

⚠️ **短版能成立的前提是 `RECALL` 字段已经落地** —— 中途靠它触发,而不是靠开头这一遍。
在 RECALL 落地之前,用完整版。

## 为什么把「形态」交给执行方

2026-08-17 一个会话内,实施方停机 6 次。**前 5 次都是真该停**
(上游判断错 · 指令会把代码改坏 · 缺数据无法继续)。
**只有第 6 次不该停** —— 他手上有一个满足全部约束、不违反任何禁令的更好写法,
却因为工单规定了形态而必须回来问。

而且他两次给出的替代方案**都比设计方原来的好**。

⇒ **能真正跑门的人知道设计方不知道的事。** 把形态规定死,就把这部分能力关掉了,
并且让每一次「更好的想法」都变成一个往返。

**工单给不变量,执行方给形态** —— 这不是放松,是把判断放在有能力判断的那一侧。

## 第二类停机为什么单列

2026-08-17 一个会话内,实施方停机 **4 次,4 次都证明是上游(设计/评审方)错了**,
而且**四次他都没有卡住** —— 是指令本身错了。

若按字面执行,那四次分别会:恢复一条被明令禁止的校验 · 去建一道详设没授权的门 ·
在错误分母上产出整份盘点并去修三个本来正确的服务 · 在缺少成员清单时臆造一个集合。

⇒ **停机纪律不是「不确定时的求助通道」,它是下游对上游错误的唯一拦截点。**
高价值的停机发生在实施方**很确定**的时候。
