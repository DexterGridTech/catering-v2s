# 商品元数据统一维护弹窗

- status: `ACTIVE`
- decisionOwner: Dexter
- effectiveDate: 2026-08-17

## 决定

运营管理后台的“商品字典与关联维护”改为一个 **Ant Design Modal**，用于统一维护当前商品库所需的元数据。
它按用户任务聚合界面，但不合并 owner 事实或命令：目录字典继续走 catalog owner，商品处理标签继续走
fulfillment-production owner 的生成接口。

该弹窗固定四个顶层实体 Tab：商品标签、销售单位、SKU 销售属性、商品处理标签。SKU 销售属性 Tab
维护属性及其必须隶属某个属性的属性值；属性值不是无父级的第五个顶层字典。分类、商品、SKU、点单选项组
及库存/BOM 不是这个元数据弹窗的实体，仍留在各自的业务工作面。

## 交互约束

- 每个 Tab 只呈现本实体（SKU 属性 Tab 呈现它的子聚合）的列表与 CRUD，不得把不同实体的缓存结果渲染到
  当前 Tab。
- 表格将“名称”和“编码”拆为两个列；不向业务用户展示并发 `version` 等技术字段。
- 元数据没有用户排序语义：不显示排序列、上移、下移或拖动排序入口，也不从该 UI 调用重排命令。
- 生产履约的商品处理标签在同一弹窗中维护，保留类型、状态、创建、改名和状态迁移；它不是 catalog
  dictionary kind。
- Tab 只能由用户点击或弹窗本次打开时的入口初值改变。异步查询、缓存失效、refetch 或其他父组件重渲染
  不得重置当前 Tab。
- 每个顶层实体使用独立的表单状态与字段标签；不能以一个无实体标签的内联通用表单承载多个 Tab。
- 编码是业务给定的非空、创建后不可修改的身份文本，不强制转换为大写，也不限制为英数字/下划线/短横线。
  唯一性由创建命令在提交时按 owner scope 裁决并反馈；不得在输入失焦时为“编码可用性”额外发请求。

## 非目标

本决定不改变 owner 数据模型、生成 OpenAPI、数据库中的历史 display-order 字段，亦不授权把
`ORDER_OPTION_VALUE` 伪装成全局商品元数据。现有未被 UI 调用的重排操作不构成前端行为。
