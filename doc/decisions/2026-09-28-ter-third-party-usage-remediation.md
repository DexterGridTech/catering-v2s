### 选项 1–6

1. **整改批次**：“检测器先行 + 高价值小批”。先接入 lint、原生单测例行入口和 DEV 双态测试，并修复主题、拓扑读超时、解压上限、锁序、React 单实例声明和设备身份 key；后续 UI、原生、测试迁移和格式化按阶段 A→B→C→D 顺序实施。该顺序属于一个原子交付批次，不拆成独立交付或 review。
2. **D-7 禁止范围**：只禁止长按弹出的系统选择/粘贴菜单，不限制其他粘贴途径。
3. **开层与关层时的焦点**：关层后不自动回到原输入框；开层期间，硬件键盘或扫码输入不得写入被弹层遮住的输入框。
4. **screen 崩溃恢复**：保留 `SystemFailureNotice` 的呈现与位置；原“点按后重新挂载 screen”已由 Dexter 后续裁定替换为唯一“知道了”按钮调用 port 重启 JS（非原生）。
5. **layer 崩溃恢复**：同一提示与按钮，原“重新挂载 layer”动作同样替换为重启 JS；不得绕过登录守卫，AdminLauncher 保持可用。
6. **Sentry**：选择延期并登记 HANDOFF。本次只落实 T-3 的错误边界，捕获错误仍写结构化日志；Sentry 的离线队列、上传窗口、脱敏、上报服务与 DSN 均待单独授权。

### 后续裁定与明确影响

- 拓扑验收用的两台 laptop VM 允许清 App 数据，以便完整执行配对与会员旅途；该许可不适用于 TP-A11 的单机双屏真机和 mobile VM。
- 测试渲染器选择 RNTL v14，一次迁移；先完成 v14 POC，临时 POC 改动不保留为实施成果。
- sw≥600dp 的设备竖屏不支持；mobile 竖屏形态仍支持。
- 不启用前台服务；应用持续位于前台的假设按 Dexter 裁定成立。
- 按键音跟随系统设置。
- 用户最终验收分为非拓扑（单机双屏真机与 mobile VM）和拓扑（两台单机单屏 laptop VM）两组，均须完成。

## 技术栈裁定对齐

- T-3 由本批落实 `react-error-boundary` 的 screen/layer/surface-content 错误边界和结构化日志；唯一恢复动作经新 command→actor→`appControl.resetRuntime` 重启 JS，不重启原生进程。Sentry 部分保持待办。
- T-4 的 React Hooks 规则按现行 TER 技术栈裁定落实。
- 拓扑端口仅用于可信门店局域网；M-3 按 Dexter 对 D-1 的选择接受风险。本决定不增加认证或信任握手。
- 本决定与需求 v3.4 中 D-1 至 D-8、TP-A1 至 TP-D4、TP-X1 至 TP-X3 的范围一致，不覆盖需求以外的功能或环境。
