# Verification-gate red fixtures

Each R4 validator executes its red fixture through the same production function against a disposable scratch copy. The mutations cover the production-read R3 route-face registry, foundation reverse import, lifecycle idempotency, DDL restriction, query budget, TDS-local MQ/outbox use, approved TDS runtime source shape, generated route registry, UI carry-over trace, terminology, value-side plaintext logging, retirement residue, and affected-L2 registry shape. The project-memory and seed-fixture checks also prove that the required NO_MQ_OUTBOX_TDP assertion and tdp=FORBIDDEN contract remain in force. The fixtures are created and removed in-process so they cannot become a runtime or seed input.
